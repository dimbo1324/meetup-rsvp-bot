# meetup-rsvp-bot

Telegram-бот для записи на еженедельные встречи русскоязычного сообщества в Монтевидео:
ограниченное число мест (по умолчанию 10), поимённая запись, лист ожидания, бан за неявку,
управление из Telegram без правки кода.

Как это выглядит: ведущий набирает `@имябота` в чате сообщества и выбирает встречу — в чат
уходит пост с кнопками «Записаться» и «Отменить запись». Постов одной встречи может быть
сколько угодно в разных чатах, счётчик мест у них общий. Бот сам в чаты не публикует и в них
не состоит; он состоит только в закрытом служебном чате ведущих.

Прогресс разработки — [`docs/ROADMAP.md`](docs/ROADMAP.md). Памятка для ведущего —
[`docs/admin-guide.md`](docs/admin-guide.md).

## Что умеет бот

Значения ниже — по умолчанию (встреча в пятницу 16:30–18:30, часовой пояс Монтевидео); всё меняется
в `/menu` → ⚙️ Настройки без правки кода.

**Участники** нажимают кнопки под постом, имён других людей они не видят:

- «Записаться» — запись на встречу; записаться можно и после её начала, пока не закрылась запись
  (через 60 минут) и есть места. Нет мест — человек встаёт в лист ожидания и получает место, когда оно
  освободится;
- «Отменить запись» — до дедлайна (день до встречи, 20:00); после него отменить может только ведущий;
- неявку отмечает ведущий; за неё человек попадает в бан и больше не может записываться (по умолчанию
  после первой неявки), пока ведущий не снимет бан;
- `/start` в личке с ботом включает напоминания и сообщения об освободившемся месте; `/start` по ссылке
  из окна записи покажет, на что человек записан.

**Ведущие** (админы) управляют ботом в личке через `/menu`: встречи, участники, чёрный список, настройки,
тексты, админы (только владелец). Пост рассылается через inline-режим: в любом чате набрать `@имябота` и
выбрать встречу. Список всех участников и CSV-выгрузка доступны только им.

**Бот сам:**

- создаёт следующую встречу в субботу в 10:00 и пишет об этом в служебный чат;
- за 2 дня до встречи в 10:00 напоминает в служебном чате, если пост ещё не разослан;
- за сутки напоминает записавшимся в личку (если они нажимали «Старт»);
- через 60 минут после начала закрывает запись и присылает итоговый список в служебный чат;
- через 90 минут после начала просит каждого ведущего отметить явку (список ✅/🚫 в личке);
- каждый день в 04:00 делает копию базы и отправляет её документом в служебный чат.

**Чего бот не делает:** не пишет в чаты сообщества сам, не состоит в них, не удаляет людей из чатов.

## 1. Быстрый старт локально

Так запускают бота для разработки и для проверки в тестовой группе. Нужны
[Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/); Python 3.14 uv поставит сам.

```bash
git clone https://github.com/dimbo1324/meetup-rsvp-bot.git
cd meetup-rsvp-bot
uv run python dev.py setup      # зависимости, .env из .env.example, pre-commit-хуки
```

Заполните `.env` (комментарии внутри файла объясняют каждую строку):

- `BOT_TOKEN` — токен **своего тестового бота** (раздел 2). Один токен — один запущенный
  процесс: если тот же токен работает где-то ещё, процессы будут перехватывать друг у друга
  обновления. Боевой токен локально не используется никогда;
- `OWNER_IDS` и `SERVICE_CHAT_ID` — раздел 3;
- `ENV=dev` — бот показывает ID и принимает команду `/dev_shift` для проверки напоминаний.

```bash
uv run python dev.py run        # применяет миграции БД и запускает бота
```

База появится в `data/bot.db`. Остановить бота — `Ctrl+C`. Если `.env` заполнен неверно,
бот сразу завершится (код 2) и напишет в консоль, какая переменная не задана (значения не
печатаются). Если Telegram отклонил токен или нет связи, код выхода 1.

Проверить окружение: `uv run python dev.py doctor`.

### Переменные `.env`

| Переменная | Обязательна | Что это |
|---|:-:|---|
| `BOT_TOKEN` | да | Токен из @BotFather (`123456789:AA…`) |
| `OWNER_IDS` | да | Telegram ID владельцев через запятую, без пробелов; хотя бы один |
| `SERVICE_CHAT_ID` | да | ID закрытой служебной группы, в которой состоит бот |
| `DATABASE_URL` | нет | Путь к SQLite; в Docker его задаёт `compose.yaml` |
| `ENV` | нет | `prod` (по умолчанию) или `dev`: при `dev` бот показывает ID и работает `/dev_shift` |
| `LOG_LEVEL` | нет | `DEBUG`, `INFO` (по умолчанию), `WARNING`, `ERROR` |
| `SENTRY_DSN` | нет | DSN Sentry; пусто — отчёты об ошибках выключены |
| `APP_VERSION` | нет | Версия в сообщении «Бот запущен»; образ получает её при сборке (раздел 4.6) |

Подробности — [раздел 15 спецификации](docs/spec/15-configuration.md).

## 2. Настройка бота в @BotFather

Делается один раз для каждого бота — и для тестового, и для боевого. Откройте
[@BotFather](https://t.me/BotFather):

| Команда | Что выбрать | Зачем |
|---|---|---|
| `/newbot` | Имя (видят все) и username, оканчивающийся на `bot` | BotFather выдаст токен — это `BOT_TOKEN`. Никому его не пересылайте |
| `/setinline` | Выбрать бота, ввести подсказку `Выберите встречу…` | Включает inline-режим: ведущий рассылает пост, набрав `@имябота` в чате |
| `/setinlinefeedback` | **Enabled** | **Обязательно.** Без этого бот не узнает о разосланных постах и не сможет обновлять в них счётчик |
| `/setjoingroups` | **Enable** | Чтобы добавить бота в служебный чат. После добавления можно вернуть Disable — тогда посторонние не добавят бота в свои группы |
| `/setprivacy` | Оставить **Enabled** (значение по умолчанию) | Боту не нужно читать переписку в группах |
| `/setdescription`, `/setabouttext`, `/setuserpic` | Например, «Бот для записи на встречи сообщества» и аватар | По желанию: это видно людям в профиле бота |

Список команд (`/start`, `/menu` и т. д.) бот выставляет сам при запуске — `/setcommands`
не нужен. Если токен утёк: `/revoke` в @BotFather, новый токен — в `.env`, перезапуск бота.

## 3. Как узнать свой Telegram ID и ID служебного чата

ID пользователей и чатов в Telegram общие для всех ботов, поэтому их удобно узнать тестовым
ботом, запущенным локально с `ENV=dev`. Чтобы бот запустился без настоящих значений,
временно впишите в `.env` заглушки `OWNER_IDS=1` и `SERVICE_CHAT_ID=0`.

1. **Свой ID.** Напишите боту в личку `/start`. В ответе будет строка
   «ID пользователя: …». Впишите это число в `OWNER_IDS`. Владельцев может быть несколько,
   через запятую.
2. **ID служебного чата.** Создайте закрытую группу (только ведущие), добавьте в неё бота.
   Бот напишет в группу «ID этого чата: …» — это `SERVICE_CHAT_ID` (обычно отрицательное
   число, у супергрупп начинается с `-100`).
3. Остановите бота, впишите настоящие значения в `.env` и удалите локальную тестовую базу
   `data/bot.db`: заглушка из `OWNER_IDS` успела записаться в неё как владелец. Запустите
   бота снова — в служебном чате появится «Бот запущен, версия …».

Боевого бота добавьте в ту же служебную группу (или в отдельную для прода — ID узнайте так
же, через тестового бота). В режиме `prod` бот ID не показывает, но пишет в лог строку
`бот добавлен в чат: chat_id=…`.

Если поменять тип или настройки группы так, что Telegram превратит её в супергруппу, ID
чата изменится. Признак — сообщения в служебный чат перестали приходить, а в логе
`служебное сообщение не доставлено`. Узнайте ID заново и обновите `.env`.

## 4. Развёртывание на VPS

Боту хватает самого маленького сервера: 1 ГБ памяти, 1 ядро, x86_64 или ARM. Подходит
Oracle Cloud Always Free или любой VPS за $4–5 в месяц; выбор и риски — в
[разделе 17 спецификации](docs/spec/17-deploy-ops.md). Входящие порты боту не нужны: он сам
опрашивает Telegram. Открыт только SSH (22).

Образ собирается прямо на сервере из этого репозитория. Автоматический деплой из GitHub
(`deploy.yml`) появится позже и для запуска не нужен.

Ниже — Ubuntu 24.04. Команды с `sudo` выполняет пользователь с правами администратора
(на Oracle это `ubuntu`).

### 4.1. Пользователь для бота

```bash
sudo adduser --disabled-password --gecos "" deploy
sudo mkdir -p /home/deploy/.ssh
sudo cp ~/.ssh/authorized_keys /home/deploy/.ssh/
sudo chown -R deploy:deploy /home/deploy/.ssh
sudo chmod 700 /home/deploy/.ssh && sudo chmod 600 /home/deploy/.ssh/authorized_keys
```

Теперь под `deploy` можно заходить тем же SSH-ключом.

### 4.2. Docker Engine и плагин compose

Официальный репозиторий Docker
([инструкция](https://docs.docker.com/engine/install/ubuntu/)):

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker deploy
sudo apt-get install -y unattended-upgrades   # автоматические обновления безопасности
```

Членство в группе `docker` равносильно правам root — добавляйте туда только `deploy`.
Проверка (под `deploy`, после повторного входа): `docker compose version`.

### 4.3. Код

```bash
sudo mkdir -p /opt/meetup-rsvp-bot
sudo chown deploy:deploy /opt/meetup-rsvp-bot
sudo -iu deploy
git clone https://github.com/dimbo1324/meetup-rsvp-bot.git /opt/meetup-rsvp-bot
cd /opt/meetup-rsvp-bot
```

Если репозиторий приватный, клонируйте по SSH с deploy-ключом только для чтения
(GitHub → Settings → Deploy keys).

### 4.4. Файл `.env`

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

Впишите:

```ini
BOT_TOKEN=<токен боевого бота>
OWNER_IDS=<ваш ID>
SERVICE_CHAT_ID=<ID служебного чата>
ENV=prod
LOG_LEVEL=INFO
```

`DATABASE_URL` в Docker задаёт `compose.yaml`, его не трогайте. Токен хранится только в этом
файле: не в git, не в GitHub, не в чатах.

### 4.5. Каталог данных

В контейнере бот работает не от root, а от пользователя с UID 10001. Каталог с базой должен
принадлежать ему, иначе бот не сможет создать БД:

```bash
mkdir -p data
sudo chown 10001:10001 data
sudo chmod 700 data
```

В `data/` лежат база `bot.db`, бэкапы `backups/` и служебный файл `heartbeat`.

### 4.6. Запуск

```bash
APP_VERSION=$(git rev-parse --short HEAD) docker compose up -d --build
```

`APP_VERSION` необязательна: она попадает в сообщение «Бот запущен, версия …» и помогает понять, какой
код работает. Первая сборка занимает несколько минут. При каждом старте контейнер сам проверяет
права на `data`, применяет миграции БД (`alembic upgrade head`), затем запускает бота.

Контейнер работает с минимумом привилегий: корневая файловая система только для чтения, пишет бот
лишь в `data/` и `/tmp`, пользователь не root, права Linux (capabilities) сброшены.

### 4.7. Проверка

```bash
docker compose ps                    # STATUS: Up … (healthy) — через 1–2 минуты после старта
docker compose logs --tail=50 bot    # строка «meetup-rsvp-bot …: запуск (prod)», без ошибок
```

В служебном чате должно появиться «Бот запущен, версия …». Если чат публичный или бот не видит его,
вместо этого (или вместе с этим) придёт предупреждение — в публичный чат нельзя: туда уходят копии
базы с данными участников. Затем напишите боту в личку `/start`: владельцу он ответит приветствием с
подсказкой про `/menu`.

Если контейнер в состоянии `Restarting`, смотрите логи:

- «Конфигурация неполная или неверная (.env): …» — исправьте названную переменную;
- «Telegram отклонил BOT_TOKEN» — неверный или отозванный токен;
- «Нет связи с Telegram» — сеть сервера;
- «Каталог /app/data недоступен для записи пользователю бота» — не выполнен шаг 4.5 (код выхода 2).

После правки `.env`: `docker compose up -d --force-recreate`.

Логи ограничены тремя файлами по 10 МБ. Просмотр в реальном времени:
`docker compose logs -f bot`.

## 5. Первичная настройка после запуска

Владелец пишет боту в личку `/start`, затем `/menu`. Подробно меню описано в
[памятке ведущего](docs/admin-guide.md).

1. **⚙️ Настройки → Встречи по умолчанию.** Задайте «Место» (название, например кафе и
   адрес), «Ссылка на карту» (`https://…`), «Описание в посте» и «Фото в посте». Проверьте
   «День встречи» (пятница), «Время начала» (16:30), «Длительность встречи» (120 мин) и
   «Лимит мест» (10). Эти значения получают **новые** встречи.
2. **⚙️ Настройки → Расписание** и **Правила** — проверьте значения; умолчания совпадают с
   договорённостями (отмена до 20:00 накануне, закрытие записи через 60 минут после начала,
   запрос явки через 90 минут, бан после первой неявки).
3. **⚙️ Настройки → Часовой пояс** — `America/Montevideo`.
4. **📅 Встречи.** Встреча на ближайшую пятницу может уже существовать: бот создаёт её сам
   (в служебном чате будет «Создана встреча: …»), в том числе сразу после первого запуска.
   Если она создалась до шага 1, откройте её карточку → ✏️ Редактировать и задайте место,
   описание и фото. Иначе создайте встречу: ➕ Новая встреча.
5. **👑 Админы** (видит только владелец) — добавьте ведущих. Каждый новый админ должен
   один раз написать боту `/start`: иначе бот не сможет присылать ему список для отметки явки.
6. Проверьте, что в каждом чате сообщества участникам разрешены inline-боты
   (см. [памятку](docs/admin-guide.md#если-в-чате-запрещены-inline-боты)), и разошлите
   первый пост.

## 6. Обновление

На сервере под `deploy`:

```bash
cd /opt/meetup-rsvp-bot
git log -1 --date=iso-strict --pretty=format:"%h %cd %s"     # запомните коммит для отката
git fetch
git diff --name-only HEAD origin/main -- alembic/versions   # есть ли новые миграции БД
```

**Если последняя команда ничего не вывела** (миграций нет):

```bash
git pull
docker compose up -d --build
docker compose logs --tail=50 bot
```

**Если вывела файлы миграций**, сначала сделайте ручной бэкап — без него откат будет
невозможен:

```bash
git pull
docker compose build                       # сборка, пока старый бот работает
docker compose stop bot
mkdir -p ~/bot-backups
sudo cp data/bot.db ~/bot-backups/bot-before-update-$(date +%Y%m%d-%H%M).db
docker compose up -d
docker compose logs --tail=50 bot
```

Бот остановлен перед копированием, поэтому `bot.db` полный и согласованный. Посты в чатах
после обновления продолжают работать.

## 7. Откат

```bash
cd /opt/meetup-rsvp-bot
git log -10 --date=iso-strict --pretty=format:"%h %cd %s"   # найдите прошлый рабочий коммит
git checkout <коммит>
docker compose up -d --build
```

- **Без миграций** этого достаточно.
- **Если откатываемое обновление применило миграцию**, старый код не запустится на новой
  схеме БД. Восстановите бэкап, сделанный перед обновлением (раздел 8.2), и только после
  этого запускайте `docker compose up -d --build`. Записи, сделанные после обновления,
  при этом потеряются.

Вернуться на актуальную версию: `git checkout main && git pull && docker compose up -d --build`.

## 8. Бэкапы и восстановление

### 8.1. Как делаются бэкапы

- Каждый день в 04:00 (по часовому поясу из настроек) бот копирует базу в
  `data/backups/bot-ГГГГ-ММ-ДД.db` и проверяет копию на целостность. Хранятся 14 последних.
- Ту же копию бот отправляет документом в служебный чат — это копия вне сервера на случай,
  если сервер пропадёт (файл больше 50 МБ Telegram не примет: в логе будет предупреждение).
- Перед обновлением с миграцией — ручной бэкап (раздел 6).
- Раз в месяц проверяйте, что бэкап восстанавливается: скачайте копию и запустите с ней бота
  локально (положите файл как `data/bot.db`, `ENV=dev`, **тестовый** токен).

В бэкапе персональные данные участников: не пересылайте его за пределы служебного чата.

### 8.2. Восстановление

1. Выберите копию: `sudo ls -l /opt/meetup-rsvp-bot/data/backups/` или скачайте документ из
   служебного чата и загрузите на сервер: `scp bot-2026-11-01.db deploy@<сервер>:~/`.
   Для отката после обновления берите ручной бэкап из `~/bot-backups/`.
2. Остановите бота и отложите текущую базу (не удаляйте — она может понадобиться):

   ```bash
   cd /opt/meetup-rsvp-bot
   docker compose stop bot
   OLD=data/replaced-$(date +%Y%m%d-%H%M)
   sudo mkdir -p "$OLD"
   for f in bot.db bot.db-wal bot.db-shm; do
     sudo test -e "data/$f" && sudo mv "data/$f" "$OLD/"
   done
   ```

   Файлы `bot.db-wal` и `bot.db-shm` — журнал SQLite; их тоже нужно убрать, иначе он
   смешается с восстановленной базой.
3. Положите копию на место и верните права:

   ```bash
   sudo cp data/backups/bot-2026-11-01.db data/bot.db    # или ~/bot-2026-11-01.db
   sudo chown 10001:10001 data/bot.db
   sudo chmod 600 data/bot.db
   ```

4. Запустите: `docker compose up -d`. Если копия старше текущего кода, недостающие миграции
   применятся при старте сами.
5. Проверьте `docker compose logs --tail=50 bot` и сообщение «Бот запущен» в служебном чате.
   Откройте `/menu` → 📅 Встречи: состояние соответствует дате бэкапа. Посты в чатах обновятся
   при следующем изменении встречи.

## 9. Вторая локация

Каждая локация — отдельная установка бота: свой бот в @BotFather (свой токен), своя база,
свои владельцы, админы, настройки и чёрный список. Код общий, на одном сервере.

1. Создайте нового бота в @BotFather (раздел 2) и служебный чат для этой локации.
2. На сервере создайте `.env.<локация>` (например, `.env.punta`) по образцу `.env.example`,
   с правами 600, токеном **нового** бота, его владельцами и служебным чатом, `ENV=prod`.
3. Каталог данных: `mkdir data-punta && sudo chown 10001:10001 data-punta && sudo chmod 700 data-punta`.
4. В `compose.yaml` раскомментируйте шаблон `bot-<локация>` и замените `<локация>` на
   `punta`.
5. `docker compose up -d --build`. Проверка, обновление и бэкапы — как для первой локации,
   с именем сервиса `bot-punta` (`docker compose logs bot-punta`) и каталогом `data-punta`.

## 10. Рабочие команды dev.py

Все рутинные задачи разработки — через `dev.py` (`uv run python dev.py list`):

| Команда | Назначение |
|---|---|
| `doctor` | проверить окружение: Python, uv, git, `.env`, `.venv`, pre-commit-хук |
| `setup` | `uv sync`, `.env` из `.env.example` (если его нет), установка pre-commit-хуков |
| `run` | применить миграции и запустить бота |
| `migrate` | только применить миграции (`alembic upgrade head`) |
| `test` | pytest (аргументы передаются дальше: `dev.py test -k waitlist`) |
| `format` / `lint` / `typecheck` | ruff format и исправления / ruff без правок / mypy |
| `quality-gate` | полный шлюз: синхронизация правил, паритет зеркал, lint, mypy, pytest |
| `sync-agents` | перегенерировать `AGENTS.md` из `.ai/` (`--check` — только проверить) |
