## Что важно знать о поведении сейчас

- **Источник — только `DomSource`**, пока `RCBOT_API_URL` пуст. По SPEC 2.3 он опрашивает не
  чаще раза в 60 секунд; 20 секунд станут возможны с `ApiSource` после разведки (этап 3).
- **`DomSource` видит дни, а не время.** Чтобы увидеть часы, день пришлось бы нажать, а это выбор
  даты (SPEC 0.3, правило 1). Время появится в тревоге вместе с `ApiSource`, если API его отдаёт.
- **Признаки страниц и шаги входа** взяты из записи экрана и на живом сайте не проверены
  (`pages.py`, `auth.py`); проверка — `rcbot login --check` на этапе 3.
- **Шаг 1** бот не проходит: `NEEDS_MANUAL`, кнопка «Готово», перепроверка раз в 15 минут.

## Проверено без сети при разработке

`DomSource` на локальном макете календаря (три месяца, зелёные дни, ячейки соседнего месяца
не считаются, снимок только календаря); цикл опроса на синтетическом сценарии (появление,
изменение, повторный вход, сбои сети, 429, шаг 1, закрытие); рассылка на фальшивых каналах
(первая волна — доли миллисекунды после события, повторы по расписанию, остановка по «Вижу»);
слой хранения на реальном файле БД; миграция (upgrade, check, downgrade); сборка диспетчера
Telegram; один экземпляр и защита от сна. Это не тесты в репозитории — они пишутся на этапе 2.
