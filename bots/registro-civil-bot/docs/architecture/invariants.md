# Инварианты: registro-civil-bot

Что нельзя ломать ни в одной фазе. Источник — SPEC.md, раздел 0.3 (жёсткие границы) и 2.6.
Изменение этого файла — только с явного одобрения владельца. Каждый инвариант по мере
реализации получает тест или проверку в коде; граница, описанная только здесь, не граница.

1. **Только чтение.** Код не выбирает дату, не нажимает «Siguiente» и «Guardar y Cerrar», не
   платит, не меняет черновик заявки.
2. **Один аккаунт, один IP.** Только аккаунт владельца, без прокси и подмены отпечатка браузера.
3. **Интервал опроса не ниже 10 с**, зашит в коде; ни `.env`, ни Telegram не задают меньше.
   В режиме `DomSource` — не ниже 60 с.
4. **Отступление при ошибках.** На 403/429/5xx — экспоненциальная пауза, а не повтор в лоб.
5. **Контрольный вопрос не решается.** Шаг 1 проходит владелец; бот зовёт его кнопкой «Готово».
6. **Личные данные не покидают ноутбук.** Паспорт, имя, почта, телефон, пароль, cookies — ни в
   логах, ни в БД, ни в фикстурах, ни в коммитах, ни во внешних каналах (ntfy, CallMeBot,
   Sentry). Номер заявки и этапа — только в локальном `.env` (решение R1).
7. **Секреты — только в Windows Credential Manager** (keyring, служба `rcbot`).
8. **Сеть — только по списку разрешённых хостов** (SPEC 2.6), TLS проверяется всегда.
9. **Тесты не ходят на живой сайт**: только фикстуры и фальшивый сервер.
10. **Telegram отвечает только владельцу** (фильтр `chat_id` в middleware).
