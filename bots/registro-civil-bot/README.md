# registro-civil-bot (rcbot)

Круглосуточно следит за публичной страницей записи в Registro Civil (Уругвай, система SAE
`sae.mec.gub.uy`) и мгновенно сообщает владельцу, когда появляются свободные места: в Telegram,
push через ntfy и звонком через CallMeBot. Записывается владелец сам — бот только читает страницу.

Полное ТЗ — [SPEC.md](SPEC.md). План и прогресс — [docs/ROADMAP.md](docs/ROADMAP.md).
Что нельзя ломать — [docs/architecture/invariants.md](docs/architecture/invariants.md).
Как устроен код — [docs/architecture/overview.md](docs/architecture/overview.md).

> **Состояние:** бот работает на ноутбуке владельца через страницу SAE (решения R12, R13 в
> [docs/open-questions.md](docs/open-questions.md)). Даты в тревоге пока не указываются: бот
> видит, что места появились, а даты владелец смотрит на странице записи.

## Платформа

Один ноутбук с Windows 11, Python 3.14, `uv`. Бот — часть монорепозитория: всё, что к нему
относится, лежит в этом каталоге (`data/`, `logs/`, `.cache/` в git не попадают). Вне каталога —
только секреты в Windows Credential Manager, задание Планировщика и журнал наблюдения
`rcbot-journal` на рабочем столе (решение R6, см. ниже). Браузер боту не нужен.

Переменная окружения `RCBOT_HOME` (необязательная) переназначает каталог бота: оттуда берутся
`.env`, `alembic.ini`, `data/`, `logs/`, `.cache/`. Без неё — каталог `bots/registro-civil-bot/`.
Нужна тестам и особым случаям; в обычной работе её не задают.

## Быстрый старт (Windows 11)

Нужен только Windows 11 с интернетом; Python и зависимости поставит `uv`.

1. Скачайте репозиторий (`git clone` или архив с GitHub) и распакуйте в любую папку.
2. Откройте папку `bots\registro-civil-bot\scripts` и дважды щёлкните **`quickstart.cmd`**
   (или в PowerShell из корня: `bots\registro-civil-bot\scripts\quickstart.cmd`). Скрипт:
   - проверит `uv` и предложит поставить его через `winget`;
   - поставит зависимости (несколько минут, один раз);
   - запустит мастер `rcbot init`: спросит номер этапа и номер заявки (из адресной строки и
     списка «Bandeja de entrada» на bpmgob — они нужны только для ссылки в тревоге), токен
     Telegram-бота (скрытым вводом) и @username для звонков и положит их в Диспетчер учётных
     данных Windows. Тему ntfy создаст сам и покажет;
   - проверит окружение (`rcbot doctor`) и предложит включить автозапуск при входе в Windows.
3. Дальше команды запускаются коротко, из любой папки: `scripts\rcbot.cmd <команда>`.

```text
rcbot.cmd doctor          полная проверка окружения и доступа к сайтам
rcbot.cmd check --once    одна проверка страницы записи
rcbot.cmd simulate        тестовая тревога во все каналы
rcbot.cmd run             работа в этом окне; постоянная — через автозапуск
```

Скрипту можно передать `-SkipInit` (пропустить мастер) и `-SkipAutostart` (не спрашивать про
автозапуск). Повторный запуск безопасен: сделанное раньше не затирается. Что нужно сделать
самому до начала (бот в @BotFather, приложение ntfy, @CallMeBot) — в конце этого файла.

## Подготовка окружения для разработки

Из **корня** монорепозитория:

```powershell
uv run python dev.py setup --bot registro-civil-bot   # зависимости, .env, хуки pre-commit
uv run --all-packages rcbot init                      # .env, номер этапа и заявки, секреты, тема ntfy, chat_id
uv run --all-packages rcbot doctor                    # проверка всего
```

Если тему ntfy кто-то увидел, создайте новую: `rcbot.cmd init --new-ntfy-topic`, затем
подпишитесь на неё в приложении ntfy (старую подписку удалите).

## Откуда бот берёт данные

Единственный источник — публичная страница записи SAE (решения R12, R13): она открывается без
входа и без контрольного вопроса. Бот только читает её обычным HTTPS-запросом, ничего не нажимает
и форм не отправляет. Пока на странице видна надпись «no hay cupos disponibles», мест нет. Когда
надпись пропадает, приходит тревога во все каналы; даты в ней пока не указываются — откройте
запись сами. Снимки страницы бот сохраняет в `data/shots/` (по ним потом допишется разбор дат).

В аккаунт gub.uy бот не входит и номер паспорта с паролем не хранит. Если они остались от
прежних версий в Диспетчере учётных данных, `rcbot init` их удалит.

`setup` создаёт `bots/registro-civil-bot/.env` из `.env.example`. В `.env` — только несекретные
настройки: номер этапа в `RCBOT_AGENDA_URL` и номер заявки в `RCBOT_TRAMITE_ID`. Секреты (токен
Telegram, тема ntfy, @username для звонков) в файлы не пишутся: их спрашивает `rcbot init` и
кладёт в Windows Credential Manager.

## Команды

Все — из корня репозитория через `uv run --all-packages rcbot <команда>`:

| Команда | Что делает |
|---|---|
| `init [--new-ntfy-topic]` | Мастер: создаёт `.env` из `.env.example`, если его нет; спрашивает номер этапа (можно весь адрес шага «Agenda») и номер заявки и пишет их в `.env`; секреты в Credential Manager, тема ntfy (`--new-ntfy-topic` — новая), определение вашего chat_id |
| `doctor [--offline] [--full]` | Версии, секреты, настройки, OneDrive, доступ к хостам, часы; `--full` — ещё `pip-audit` |
| `check --once` | Одна проверка страницы записи: «мест нет» или «места появились» |
| `run` | Постоянная работа (для отладки в консоли; в обычной жизни — через Планировщик) |
| `simulate [--wait 600]` | Тестовая тревога во все каналы с повторами до «Вижу» |
| `purge` | Удалить логи, временные файлы, снимки, кеш и остатки прежних версий (карантин, дампы разведки, Chromium в `.browsers/`); база и `.env` остаются |
| `uninstall` | Удалить секреты из Credential Manager и задание Планировщика |

Ни `purge`, ни `uninstall` не трогают журнал наблюдения: папку `rcbot-journal` на рабочем столе
(или `RCBOT_JOURNAL_DIR`) после удаления бота удалите вручную.

Автозапуск: `powershell -ExecutionPolicy Bypass -File bots\registro-civil-bot\scripts\register_task.ps1`
(при входе в Windows, без окна, перезапуск при сбое). В настройках питания от сети: «Переводить
в спящий режим» — «Никогда», закрытие крышки — «Ничего не делать».

## Журнал наблюдения на рабочем столе

Папка `rcbot-journal` на рабочем столе (путь меняется настройкой `RCBOT_JOURNAL_DIR`). Её можно
смотреть в любой момент, даже когда мест нет:

| Что | Где |
|---|---|
| Текущее состояние, «жив / завис» | `status.json` — `alive_at` обновляется каждые 30 с; если он старше нескольких минут, бот не работает |
| Каждая проверка страницы | `checks/checks-ГГГГ-ММ-ДД.jsonl` — время, источник, найденные места или ошибка, время ответа |
| Каждое действие и событие | `events/events-ГГГГ-ММ-ДД.jsonl` — смены состояния, тревоги, доставки, «Вижу», команды, зависания, очистки |
| Подробный лог | `logs/rcbot-ГГГГ-ММ-ДД.log` |
| Когда открывались окна записи | `openings.csv` — открывается в Excel |

Если папка больше `RCBOT_JOURNAL_MAX_GB` (10 ГБ), бот сам удаляет самые старые дни, пока не
останется `RCBOT_JOURNAL_TRIM_TO_GB` (5 ГБ); сегодняшние файлы и статистика окон не удаляются.
Секретов, cookies и номеров заявки в журнале нет.

Если ноутбук спал, бот это замечает: в `events` появляется запись `system.sleep`, в `status.json` —
`last_sleep_*` и `sleeps_total_sec`, а в Telegram приходит «Ноутбук спал с … до …» (сон не короче
5 минут). Пока ноутбук спит, бот ничего не проверяет.

Если проверка зависнет дольше 150 секунд, она прерывается; если встанет весь цикл опроса, бот
сам перезапустит его и напишет об этом в Telegram.

Запись журнала идёт в фоновом потоке (`RCBOT_JOURNAL_BACKGROUND`, по умолчанию включено): проверка
не ждёт диска. `false` — запись в том же потоке, нужно только отладке и тестам.

## Тесты

```powershell
uv run python dev.py test --bot registro-civil-bot          # весь набор и порог покрытия 85 %
uv run python dev.py quality-gate --bot registro-civil-bot  # плюс ruff, mypy, раскладка
```

Тесты идут без сети и без настоящих данных; устройство набора — `docs/testing.md`.

## Управление из Telegram

`/help` (и `/start`) — список команд; `/status`, `/pause [минуты]`, `/resume`, `/interval <сек>`
(не меньше 10), `/test`, `/last`, `/cleanup`, `/menu`. Тревога подтверждается кнопкой «✅ Вижу»
или словом «ок».

## Что владелец делает сам (SPEC.md, 9.1)

1. Создать бота у @BotFather и написать ему `/start`.
2. Поставить на телефон приложение ntfy.
3. Написать `/start` боту @CallMeBot_txtbot и разрешить звонки.
4. Ввести токен и @username в `rcbot init`, подписаться на тему ntfy, ответить на тестовый звонок.
