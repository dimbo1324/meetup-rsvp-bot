# SPEC: бот-наблюдатель за записью в Registro Civil (Уругвай)

Версия 1.0 от 11.11.2026. Документ — техническое задание для реализации в Claude Code.
Копия в монорепозитории: номер заявки и номер этапа владельца заменены метками `<НОМЕР_ЗАЯВКИ>` и `<НОМЕР_ЭТАПА>`;
реальные значения живут только в локальном `.env` (см. `docs/open-questions.md`, решение R1).
Объём v1: **один ноутбук (Windows), один аккаунт gub.uy, один получатель уведомлений**.

## 0. Контекст, задача, план

### 0.1. Что происходит

Владелец (гражданин РФ, живёт в Монтевидео) должен зарегистрировать иностранное свидетельство о рождении в Registro Civil. Услуга: **«Inscripción de partidas extranjeras — Trámite exclusivo para titulares de documentos extranjeros»**.

Запись на приём идёт через сайт Министерства образования и культуры (MEC), система `bpmgob.mec.gub.uy`. Свободных дат почти никогда нет: по сообщениям в мигрантских чатах, новые места появляются редко (называли время около 21:00) и расходятся за секунды или минуты.

У владельца уже создана заявка-черновик, она стоит на шаге 2 «Agenda» (выбор даты). На 11.11.2026 календарь с ноября 2026 по март 2027 показывает «No hay cupos disponibles».

### 0.2. Задача бота

Круглосуточно следить за календарём и **мгновенно уведомить владельца**, когда появятся свободные даты. Записывается владелец сам, руками.

### 0.3. Жёсткие границы (не обсуждаются)

| № | Правило |
|---|---|
| 1 | Бот **только читает** календарь. Он не выбирает дату, не нажимает «Siguiente», «Guardar y Cerrar», не платит, не меняет черновик. |
| 2 | Бот работает **только с аккаунтом владельца**, с одного IP, без прокси и без подмены отпечатка браузера. |
| 3 | Интервал опроса не ниже **10 секунд** (жёсткий минимум в коде). По умолчанию 20 секунд. |
| 4 | При ответах 403/429/5xx бот **снижает частоту** (экспоненциальная пауза), а не пытается пробиться. |
| 5 | Контрольный вопрос на шаге 1 («Verificación de seguridad») бот **не решает**. Если сайт требует пройти шаг 1, бот зовёт владельца кнопкой в Telegram. См. раздел 9, решение D3. |
| 6 | Никакие личные данные (паспорт, имя, почта, телефон, пароль, cookies) не уходят с ноутбука. |

«Скрытность» в этом документе значит **приватность**: нет утечек, нет лишних следов на диске, фоновая работа без окна. Это не про обход защиты сайта.

### 0.4. План реализации (фазы)

| Фаза | Что делаем | Результат |
|---|---|---|
| 0. Разведка | Записать сетевые запросы шага «Agenda», разобрать API календаря (решение D1) | Очищенный дамп запроса и ответа, фикстуры для тестов |
| 1. Каркас | Проект, конфиг, секреты, логи, БД, миграции, CLI | `rcbot doctor` проходит |

| 4. Детектор и инциденты | Сравнение снимков, открытие и закрытие инцидентов | Юнит-тесты зелёные |
| 5. Уведомления | Telegram, ntfy, CallMeBot, повторы до подтверждения | `rcbot simulate` поднимает все три канала |

### 1.3. Что известно о сайте (наблюдения из записи экрана)

**Платформа.** `bpmgob.mec.gub.uy`, внизу страниц «Versión 3.6-T». Судя по именам cookies, это BPM-платформа SIMPLE. Перед ней стоит защитный шлюз (cookies с префиксом `TS…`, характерны для F5). Вывод: частые запросы могут вызвать блокировку, поэтому правила 3 и 4 из раздела 0.3 обязательны.

**Cookies сессии (только имена):** `simple_bpm_session`, `simple_bpm_saml_s…`, `simple_bpm_login_c…`, `simple_bpm_location`, `simple_bpm_query`, `target_bal`, `TS0191f197`, `TS01d82af7`. Local Storage и Session Storage пусты.

**Шаги заявки:** «Datos necesarios» (1) → «Agenda» (2) → «Efectuar pago» (3). Заголовок шага: «Paso 2 de 3».

**Страница шага 2 «Agenda»:**
- Радиокнопка «Seleccionar ubicación: Oficina Tramite Extranjeros». Календарь появляется после её выбора.
- «Preferencia de horario»: Cualquier horario / Solo por la mañana / Solo por la tarde.
- «Seleccionar día»: календарь jQuery UI Datepicker (один месяц, стрелки влево и вправо).
- Подсказка на странице: «Los días marcados en color verde tienen turnos disponibles». После выбора дня под календарём появляются часы.
- Если мест нет, под календарём красная плашка **«No hay cupos disponibles»**.
- Кнопки внизу: «Volver», «Guardar y Cerrar», «Siguiente». Бот их не трогает.

**Сетевые запросы шага 2 (вкладка Network):**
- XHR **`agenda_sae_api_disponibilidades`**: инициатор jQuery, ответ около 0,4 kB, время около 350 мс. Это запрос доступных дат. Полный URL, метод, параметры и формат ответа **пока неизвестны** — это задача фазы 0.
- XHR `calendario-sae.js?_=<метка времени>`: скрипт календаря, подгружается динамически. В нём, вероятно, виден код вызова API. Его нужно прочитать в фазе 0.
- Библиотеки страницы: jQuery 1.8.3, jQuery UI 1.11.4, `datepicker_accesible.js`, `calendario-sae.css`, OpenLayers 3.5 (карта), `socket.io.js`.

**Селекторы для запасного режима (проверены на макете, не на живом сайте):**
- таблица календаря: `.ui-datepicker-calendar`;
- заголовок месяца: `.ui-datepicker-title`;
- стрелка «следующий месяц»: `.ui-datepicker-next`;
- свободный день: ячейка `td`, у которой фон самой ячейки или вложенного `a`/`span` зелёный (условие: `g > 110 && g > r + 35 && g > b + 25`);
- плашка «мест нет»: текст `No hay cupos disponibles`.

**Вход (проверено на видео, кода из SMS нет):**
1. Переход по ссылке входа → `mi.iduruguay.gub.uy/login?process_state=…`, страница «Elige un método para identificarte en ID Uruguay».
2. Выбрать **«Usuario Gub.uy»**.
3. Нажать **«No tengo documento uruguayo»**.
4. «País emisor» → `Rusia`; «Tipo de documento» → `Pasaporte`; «Número» → номер паспорта; кнопка «Continuar».
5. Поле «Ingresá tu contraseña» → пароль; кнопка «Continuar».
6. Переадресация `mi.iduruguay.gub.uy/sending-saml-response` → обратно в `bpmgob.mec.gub.uy`.

**Шаг 1 и контрольный вопрос.** На шаге 1 есть блок «Verificación de seguridad» с простым вопросом (примеры: «¿Cuántos minutos tiene una hora?», «¿Qué número está antes del 1?») и ссылкой «Solicitar otra pregunta». После входа и нажатия «Continuar» в списке заявок сайт открыл шаг 1. Прямой переход на URL шага 2 в той же сессии работал. Работает ли прямой переход на шаг 2 сразу после нового входа — неизвестно; поведение задано решением D3.

**Старая система SAE.** Страница SAE открывается без входа и 11.11.2026 показывала слоты на 23.02.2027 (10:30, 10:45, 11:00), тогда как bpmgob показывал «нет мест». Подтвердить бронь через SAE не удалось: ошибка «No se pudieron recuperar las preguntas de seguridad». В MEC отправлен вопрос, ответа пока нет. В v1 SAE — необязательный вторичный источник, выключен по умолчанию.

**Оплата.** По описанию услуги: 1 436 песо в течение 48 часов после выбора даты, иначе запись сгорает. Бот к оплате отношения не имеет.

**Совместимость с Python 3.14 — проверить первым делом** (`rcbot doctor`):
- Playwright зависит от `greenlet`; нужны готовые сборки под 3.14 для Windows.
- Если Playwright не ставится на 3.14: вынести вход в отдельную утилиту `tools/login_helper` со своим окружением на 3.13. Она печатает cookies в stdout в JSON, основной процесс читает их через `asyncio.create_subprocess_exec`. Основной бот остаётся на 3.14.

### 2.2. Откуда берётся скорость

Задержка от появления слота до звука на телефоне складывается из четырёх частей:

| Часть | Сейчас (прототип) | Цель v1 | Как |
|---|---|---|---|
| Ожидание следующей проверки | в среднем 2 мин | **в среднем 10 с** | Интервал 20 с, круглосуточно |
| Сама проверка | 15–30 с (браузер, 6 месяцев) | **0,3–0,6 с** | Прямой запрос к API, месяцы параллельно |
| Обработка в боте | — | **< 50 мс** | Сравнение в памяти, запись в БД после отправки |
| Доставка уведомления | 1–2 с | **0,3–1 с** | Прогретые соединения, три канала параллельно |

Что обязательно сделать для скорости:
1. **Основной режим — прямой запрос к API** (`ApiSource`) через `aiohttp`, без браузера.
2. **Одна долгоживущая `ClientSession`** на сайт: `TCPConnector(limit=4, keepalive_timeout=75, ttl_dns_cache=300)`, таймаут запроса 8 с.
3. **Прогретые соединения к каналам уведомлений**: отдельные сессии к `api.telegram.org`, `ntfy.sh`, `api.callmebot.com`, раз в 4 минуты лёгкий запрос (`getMe` для Telegram), чтобы TCP и TLS были уже установлены.
4. **Уведомление раньше записи в БД**: событие «появились места» сразу уходит в рассылку, запись в базу идёт отдельной задачей.
5. **Три канала параллельно** через `asyncio.TaskGroup`, у каждого свой таймаут и повторы; сбой одного не задерживает остальные.
6. **Планировщик без дрейфа**: следующая проверка считается от `loop.time()`, а не «сон после окончания предыдущей». Разброс ±10 %, чтобы запросы не шли с точностью метронома.
7. **Сравнение по отпечатку**: снимок календаря сводится к `frozenset` слотов и хешу; если хеш не изменился, дальше ничего не выполняется.

Честная оценка: при интервале 20 с средняя задержка обнаружения — 10 с, худший случай — около 21 с. «Околонулевая» задержка достижима только для обработки и доставки. Сократить интервал ниже 10 с нельзя (правило 3): выигрыш в секунды не стоит риска блокировки аккаунта.

### 2.3. Архитектура

Слоистая схема: доменное ядро без зависимостей, порты (интерфейсы), адаптеры.

```
┌────────────────────────── presentation ──────────────────────────┐
│  CLI (rcbot …)            Telegram-бот (aiogram + aiogram-dialog) │
└───────────────┬───────────────────────────────┬───────────────────┘
                │                               │
┌───────────────▼───────────── application ─────▼───────────────────┐
│  PollLoop → Detector → EventBus → AlertOrchestrator               │
│  SessionManager   Housekeeping   HealthMonitor   Supervisor       │
└───────┬───────────────┬────────────────┬──────────────┬───────────┘
        │ ports         │                │              │
┌───────▼──────┐ ┌──────▼───────┐ ┌──────▼──────┐ ┌─────▼──────────┐
│ Availability │ │ Authenticator│ │  Notifier   │ │  Repositories  │
│   Source     │ │              │ │  (3 канала) │ │                │
├──────────────┤ ├──────────────┤ ├─────────────┤ ├────────────────┤
│ ApiSource    │ │ Playwright   │ │ Telegram    │ │ SQLAlchemy +   │
│ DomSource    │ │ login        │ │ Ntfy        │ │ aiosqlite      │
│ (SaeSource)  │ │              │ │ CallMeBot   │ │                │
└──────────────┘ └──────────────┘ └─────────────┘ └────────────────┘
```

**Поток данных при находке:**

```
PollLoop ──(каждые ~20 с)──► AvailabilitySource.fetch()
   │                              │
   │                        AvailabilitySnapshot
   ▼                              ▼
Detector.compare(prev, new) ──► событие SlotsAppeared / SlotsChanged / SlotsGone
   │
   ▼
EventBus (asyncio, в памяти)
   ├──► AlertOrchestrator ──► TaskGroup: Telegram ‖ ntfy ‖ CallMeBot
   │         └──► повторы каждую минуту, пока владелец не подтвердит
   └──► IncidentRepository (запись в БД, не блокирует рассылку)
```

**Состояния опроса (`PollState`):**

| Состояние | Что значит | Выход |
|---|---|---|
| `RUNNING` | Обычная работа | — |
| `REAUTH` | Сессия истекла, идёт вход | Успех → `RUNNING`; 3 неудачи → `BACKOFF` и сообщение владельцу |
| `BACKOFF` | Сайт отвечает ошибками | Пауза 30 с → 1 мин → 2 мин → … до 15 мин, затем пробный запрос |
| `NEEDS_MANUAL` | Сайт требует шаг 1 | Владелец проходит шаг 1 руками и жмёт «Готово» в боте |
| `PAUSED` | Пауза по команде | `/resume` или истечение таймера |

**Сессия и вход (`SessionManager`):**
- Вход выполняет Playwright (Chromium, без окна, **временный контекст без профиля на диске**), затем `context.cookies()` переносятся в `aiohttp.CookieJar`, браузер закрывается.
- Cookies живут **только в памяти**. После перезапуска бот входит заново.
- Признак истёкшей сессии: переадресация на `/autenticacion` или `mi.iduruguay.gub.uy`, либо HTML вместо ожидаемого ответа API.
- Повторный вход защищён блокировкой (одновременно один) и лимитом: **не больше 6 входов в час**. Превышение → `BACKOFF` и сообщение владельцу.
- Владелец может сам войти на сайт в своём браузере. Если это выкидывает сессию бота, бот просто войдёт заново; после уведомления о слотах бот **не входит повторно 10 минут**, чтобы не мешать владельцу записываться (решение D5).

**Источники данных (`AvailabilitySource`, протокол):**

```python
class AvailabilitySource(Protocol):
    name: str

    async def fetch(self, target: WatchTarget) -> AvailabilitySnapshot: ...
    async def close(self) -> None: ...
```

- `ApiSource` — основной. Вызывает `agenda_sae_api_disponibilidades` напрямую. Параметры и разбор ответа пишутся по итогам фазы 0. Ответ проверяется моделью Pydantic; неожиданный формат → исключение `UnexpectedResponse` и снимок ответа в `data/quarantine/` (без cookies).
- `DomSource` — запасной. Держит одну открытую вкладку Playwright на шаге «Agenda», листает месяцы и читает зелёные дни. Включается автоматически, если `ApiSource` три раза подряд вернул `UnexpectedResponse`. Интервал в этом режиме не ниже 60 с.
- `SaeSource` — необязательный, выключен. Читает публичную страницу SAE. Его находки помечаются как «неподтверждённые» и идут только сообщением в Telegram без звонка.

**Модель инцидента:**
- Инцидент открывается, когда множество слотов стало непустым.
- Если множество изменилось (добавились новые слоты) — событие `SlotsChanged`, новое уведомление.
- Инцидент закрывается, когда слотов нет **3 проверки подряд** (защита от дребезга).
- Подтверждение владельца («Вижу») останавливает повторы для текущего инцидента, но не закрывает его.

### 2.4. Уведомления (все три канала)

Все каналы реализуют один протокол и вызываются параллельно.

```python
class Notifier(Protocol):
    channel: Channel

    async def send(self, alert: Alert) -> DeliveryResult: ...
    async def warmup(self) -> None: ...
```

| Канал | Как работает | Детали реализации |
|---|---|---|
| **Telegram** | Сообщение от собственного бота (создаётся через @BotFather) | aiogram. Текст + кнопка «✅ Вижу». Повтор **каждые 60 с**, пока владелец не нажмёт кнопку или не напишет «ок». Не больше 30 повторов на инцидент. |
| **ntfy** | Push в приложение ntfy на телефоне | `POST https://ntfy.sh/` с JSON: `{"topic": …, "title": …, "message": …, "priority": 5, "tags": ["rotating_light"]}` — без ссылки: номер этапа на сторонний сервис не уходит (решение R10). Приоритет 5 (max). Повтор каждые 2 минуты, не больше 10. |
| **CallMeBot** | Голосовой звонок в Telegram, робот читает текст | `GET https://api.callmebot.com/start.php?user=@<username>&text=<текст>&lang=<код>&rpt=2`. Звонок при открытии инцидента, затем каждые 3 минуты, не больше 5. Текст до 256 символов. |

**Настройка каналов владельцем (один раз):**
- Telegram: @BotFather → `/newbot` → токен. Написать боту `/start`.
- ntfy: поставить приложение ntfy, подписаться на тему. Имя темы — случайная строка из 32+ символов, генерирует `rcbot init`. В настройках приложения для темы включить максимальный приоритет и разрешить звук в режиме «Не беспокоить».
- CallMeBot: написать `/start` боту @CallMeBot_txtbot и разрешить звонки. Точные параметры API и лимиты сверить на странице сервиса при реализации.

**Приватность каналов:**
- ntfy.sh и CallMeBot — сторонние сервисы. Тема ntfy читается любым, кто знает её имя. Поэтому в текстах **нет личных данных**: только даты, время и общая фраза.
- Telegram-бот отвечает **только владельцу** (фильтр по `chat_id` на уровне middleware). Чужие сообщения молча игнорируются и пишутся в журнал.

**Тексты (шаблоны в `bot/texts.py`):**

```
🟢 Registro Civil: появились места!
• 23.02.2027 (вт): 10:30, 10:45, 11:00
Заявка <НОМЕР_ЗАЯВКИ> → «Realizar» → шаг «Agenda»
https://bpmgob.mec.gub.uy/etapas/ejecutar/<НОМЕР_ЭТАПА>/1
Найдено в 21:00:07, уведомление за 0,4 с.
```

Текст звонка: «Внимание. В Регистро Сивиль появились свободные места. Срочно записывайся.»

**Служебные сообщения (только Telegram, без звонка):**
- ежедневный отчёт в 09:00: число проверок, медиана и 95-й перцентиль времени ответа, число входов, ошибки;
- смена состояния: `BACKOFF`, `NEEDS_MANUAL`, переход на `DomSource`;
- запуск и остановка бота.

### 2.5. Telegram-интерфейс

**Команды:** `/help` (и `/start`: список команд), `/status`, `/pause [минуты]`, `/resume`, `/test` (проверка всех трёх каналов), `/last` (последние 5 инцидентов), `/interval <сек>` (не ниже 10), `/relogin`, `/cleanup`, `/menu`.

### 2.6. Безопасность и приватность

**От чего защищаемся:**

| Угроза | Мера |
|---|---|
| Пароль и токены лежат открытым текстом | Секреты хранятся в **Windows Credential Manager** через `keyring` (служба `rcbot`). В `.env` только несекретные настройки. |
| Секрет попал в лог или трассировку | Типы `SecretStr`. Фильтр логов `RedactionFilter` вырезает значения секретов, номер документа, cookies, заголовки `Cookie`/`Set-Cookie`/`Authorization`. Юнит-тест проверяет, что секреты в лог не попадают. |
| Папка на рабочем столе синхронизируется в облако | `rcbot doctor` проверяет, лежит ли `Desktop` внутри OneDrive. Если да — предупреждение и предложение исключить папку из синхронизации. Секретов и cookies на диске всё равно нет. |
| Утечка через Sentry | Sentry **выключен по умолчанию**. Если включён: `send_default_pii=False`, `include_local_variables=False`, `max_request_body_size="never"`, хук `before_send` прогоняет событие через тот же редактор. |
| Запрос уходит не туда | HTTP-обёртка разрешает только хосты из списка: `bpmgob.mec.gub.uy`, `mi.iduruguay.gub.uy`, `api.telegram.org`, `ntfy.sh`, `api.callmebot.com`, адрес «сторожа» (если включён), `sae.mec.gub.uy` (только при `RCBOT_SAE_SOURCE_ENABLED=true`). Остальное — исключение. Проверка TLS всегда включена. |
| Чужой человек управляет ботом | Middleware пропускает только `chat_id` владельца. |
| Личные данные в сторонних сервисах | В ntfy и CallMeBot уходят только даты и общая фраза. |
| Снимки экрана с личными данными | В режиме API снимков нет. В режиме DOM снимается **только элемент календаря** (`locator.screenshot`), хранится локально, срок 3 дня. |
| Вредная зависимость | Версии зафиксированы, `uv.lock` с хешами. `pip-audit` в `rcbot doctor --full`. |
| Два экземпляра бота одновременно | Блокировка одного экземпляра (именованный мьютекс Windows + файл `data/rcbot.lock`). |
| Данные разведки (фаза 0) | Дампы запросов очищаются от cookies и личных полей до записи на диск, хранятся 7 дней. |

**Фоновая работа:** запуск через Планировщик заданий Windows с `pythonw.exe` (без окна консоли). Управление и статус — через Telegram.

### 2.7. Данные на диске и очистка

Всё, что относится к боту, лежит в одной папке: **`%USERPROFILE%\Desktop\RegistroBot\`**. Вне её — только записи в Windows Credential Manager и задание Планировщика.

| Что | Где | Срок хранения |
|---|---|---|
| База SQLite | `data/rcbot.sqlite3` | Постоянно; старые записи чистятся (ниже) |
| Журнал | `logs/rcbot.log` | Ротация 5 файлов по 2 МБ; файлы старше 14 дней удаляются |
| Инциденты и доставки | БД | 180 дней |
| Статистика опроса | БД, **по часам** (не каждая проверка) | 30 дней |
| Журнал событий | БД | 30 дней |
| Дампы разведки | `data/discovery/` | 7 дней |
| «Карантин» неожиданных ответов | `data/quarantine/` | 7 дней, не больше 20 файлов |
| Снимки календаря (режим DOM) | `data/shots/` | 3 дня, не больше 20 файлов |
| Временные файлы | `data/tmp/` | Очищается при каждом запуске |
| Браузер Playwright | `.browsers/` (`PLAYWRIGHT_BROWSERS_PATH`) | Один актуальный Chromium; старые версии удаляются после обновления |
| Кеш байт-кода | `.cache/pycache/` (`PYTHONPYCACHEPREFIX`) | Удаляется командой `rcbot purge` |

**Правила:**
- Каждая проверка **не пишется в БД**. В память копится счётчик, раз в час в БД идёт одна строка статистики. Иначе за сутки набегало бы 4 320 строк.
- Задача `Housekeeping` запускается при старте и каждые 6 часов: применяет сроки из таблицы, раз в неделю делает `PRAGMA wal_checkpoint(TRUNCATE)` и `VACUUM`.
- БД работает в режиме WAL, `synchronous=NORMAL`.
- Профиль браузера на диск не сохраняется (временный контекст).
- `rcbot purge` удаляет логи, временные данные, карантин, снимки, кеш. `rcbot uninstall` дополнительно удаляет секреты из Credential Manager и задание Планировщика; после этого папку можно удалить целиком.
- `/status` показывает размер папки. Если он больше 300 МБ — предупреждение.

### 3.4. Требования к качеству кода

- Полные аннотации типов, `mypy --strict` без ошибок.
- `ruff` (линтер и форматирование), длина строки 100.
- Доменный слой не импортирует `aiohttp`, `aiogram`, `sqlalchemy`, `playwright`.
- Зависимости передаются через конструкторы; глобальных синглтонов нет.
- Время берётся через порт `Clock` (в тестах — фальшивые часы).
- Все сетевые вызовы — с таймаутом. Никаких «голых» `except:`.
- Корректное завершение: по Ctrl+C и по сигналу остановки задачи закрываются по порядку, соединения и браузер закрыты.
- Покрытие тестами доменного и прикладного слоёв — не ниже 85 %.

## 4. Установка и запуск

### 4.1. Что нужно заранее

- Windows 11, Python 3.14, `uv`.
- Токен Telegram-бота от @BotFather; владелец написал боту `/start`.
- Приложение ntfy на телефоне.
- Разрешение на звонки у @CallMeBot_txtbot.
- Заявка <НОМЕР_ЗАЯВКИ> стоит на шаге «Agenda» (шаг 1 пройден вручную).

### 4.2. Установка

```powershell
cd $env:USERPROFILE\Desktop\RegistroBot
uv sync                                   # окружение и зависимости по uv.lock
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.browsers"
uv run playwright install chromium
uv run alembic upgrade head
copy .env.example .env
```

### 4.3. Первичная настройка

```powershell
uv run rcbot init        # мастер: спрашивает секреты и кладёт их в Credential Manager,
                         # генерирует имя темы ntfy, определяет chat_id
uv run rcbot doctor      # проверка: версии, Playwright, доступ к хостам, OneDrive, секреты, время
uv run rcbot simulate    # тестовый «инцидент»: должны прийти Telegram, push ntfy и звонок
```

Что делает `rcbot init`: создаёт `.env` из `.env.example`, если его нет; спрашивает номер этапа (число из адресной строки шага «Agenda» или весь адрес) и номер заявки и пишет их в локальный `.env`; скрытым вводом спрашивает секреты — номер документа, пароль gub.uy, токен Telegram, @username для CallMeBot. Имя темы ntfy не спрашивается: мастер генерирует его сам и показывает владельцу.

| Источники | `RCBOT_API_URL` (пусто — `ApiSource` выключен; только хост bpmgob), `RCBOT_SAE_SOURCE_ENABLED`; адреса `RCBOT_LOGIN_URL`, `RCBOT_SAE_URL` заданы в коде |
| Опрос | `RCBOT_POLL_INTERVAL_SEC` (жёсткий минимум в коде — 10), `RCBOT_POLL_JITTER`, `RCBOT_REQUEST_TIMEOUT_SEC`, `RCBOT_RELOGIN_MAX_PER_HOUR` |
| Уведомления | `RCBOT_TG_REPEAT_SEC`, `RCBOT_TG_REPEAT_MAX`, `RCBOT_NTFY_SERVER`, `RCBOT_NTFY_REPEAT_SEC`, `RCBOT_NTFY_REPEAT_MAX`, `RCBOT_CALL_REPEAT_SEC`, `RCBOT_CALL_REPEAT_MAX`, `RCBOT_CALL_LANG` |
| Прочее | `RCBOT_TIMEZONE`, `RCBOT_DAILY_REPORT_HOUR`, `RCBOT_SENTRY_ENABLED`, `RCBOT_SENTRY_DSN`, `RCBOT_WATCHDOG_URL` (необязательно, см. 6.1), `RCBOT_HEADLESS`, `RCBOT_BROWSER` (решение R8) |
| Журнал наблюдения (R6) | `RCBOT_JOURNAL_ENABLED`, `RCBOT_JOURNAL_DIR`, `RCBOT_JOURNAL_BACKGROUND`, `RCBOT_JOURNAL_MAX_GB`, `RCBOT_JOURNAL_TRIM_TO_GB` |

Пример строки шага «Agenda» (номер — только в локальном `.env`):

```dotenv
RCBOT_AGENDA_URL=https://bpmgob.mec.gub.uy/etapas/ejecutar/<НОМЕР_ЭТАПА>/1
```

### 4.5. Разведка и первый запуск

```powershell
uv run rcbot discover     # фаза 0: открывает браузер с окном, владелец видит вход;
                          # пишет очищенные запросы в data\discovery\ и печатает сводку
uv run rcbot login --check
uv run rcbot check --once # одна проверка, печатает состояние по месяцам
uv run rcbot run          # постоянная работа в консоли (для отладки)
```

### 4.6. Круглосуточная работа

```powershell
powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1
```

Скрипт создаёт задание Планировщика: запуск при входе пользователя, `pythonw.exe -m rcbot run`, перезапуск при сбое каждую минуту (до 999 раз), без ограничения по времени.

Дополнительно на ноутбуке:
- Параметры → Система → Питание: «Переводить в спящий режим» при питании от сети — **Никогда**.
- Действие при закрытии крышки (от сети) — «Ничего не делать».
- Бот сам вызывает `SetThreadExecutionState`, чтобы система не засыпала, пока он работает.

## 6. Прочее важное

### 6.1. Внешний «сторож»

Ноутбук один. Если он выключится или потеряет сеть, бот об этом сообщить не сможет. Решение: бесплатный сервис проверки «живости» (например, healthchecks.io). Бот раз в минуту отправляет пустой запрос на личный адрес; если запросов нет 5 минут, сервис сам пишет владельцу. В запросе нет никаких данных. Адрес задаётся в `RCBOT_WATCHDOG_URL`, хост добавляется в список разрешённых.

### 6.2. Фаза 0 — что именно выяснить

`rcbot discover` открывает шаг «Agenda», листает месяцы и записывает все XHR. До записи на диск из дампа удаляются `Cookie`, `Set-Cookie`, `Authorization`, а номер документа, имя, почта и телефон заменяются на `***`.

Нужно получить:
1. Полный URL, метод и параметры `agenda_sae_api_disponibilidades`.
2. Формат ответа: что возвращается (дни, часы, число мест), на какой период.
3. Нужен ли токен защиты от подделки запросов (CSRF) или особые заголовки (`X-Requested-With`, `Referer`).
4. Текст `calendario-sae.js`: как страница вызывает API и как красит дни.
5. Отдельный ли запрос возвращает часы внутри дня.
6. Используется ли `socket.io` для обновления календаря без перезагрузки.

### 6.3. Риски

| Риск | Что делаем |
|---|---|
| Сайт заблокирует IP или аккаунт за частые запросы | Минимум 10 с, backoff, один аккаунт; при первом 403/429 — сообщение владельцу |
| Формат API изменится | Проверка Pydantic, карантин ответа, автопереход на `DomSource`, сообщение владельцу |
| Сайт требует шаг 1 после каждого входа | Решение D3: просьба владельцу кнопкой в Telegram |
| Сессия бота и ручной вход владельца мешают друг другу | Пауза повторного входа на 10 минут после уведомления |
| Ложная тревога из-за разовой ошибки | Уведомление только при корректном разобранном ответе с непустым набором слотов |
| Пропуск из-за сна ноутбука | Защита от сна, «сторож», ежедневный отчёт |
| CallMeBot или ntfy недоступны | Каналы независимы; сбой фиксируется в `deliveries` и в отчёте |
| Места уйдут быстрее, чем владелец успеет | Держать на ноутбуке открытую вкладку с заявкой; в уведомлении точные дата и время |

### 6.4. Содержимое `CLAUDE.md`

```markdown
# Правила проекта rcbot
- Источник требований: SPEC.md. При расхождении кода и SPEC.md — спросить владельца.

  «Siguiente»/«Guardar», платит или решает контрольный вопрос.
```

## 7. Тестирование

| Уровень | Что проверяем |
|---|---|
| Юнит | `detector` (появление, изменение, исчезновение, дребезг); разбор ответа API по фикстурам; `RedactionFilter`; логика повторов и подтверждения с фальшивыми часами; backoff; лимит входов |
| Интеграция | Фальшивый сервер aiohttp: сценарий «нет мест → есть → пропали»; истечение сессии (302); 429 и 503; неожиданный формат → карантин → переход на `DomSource` |
| Скорость | От получения ответа с новыми слотами до вызова всех трёх `Notifier.send` — **меньше 100 мс** на фальшивых адаптерах |
| Сквозной | `rcbot simulate`: реальные Telegram, ntfy, CallMeBot с тестовым текстом |
| Приватность | Тест ищет в логах и фикстурах известные секреты и шаблон номера документа; находка — провал |

## 8. Критерии приёмки

1. `rcbot doctor` проходит без ошибок на Python 3.14 (или задокументирован обходной путь для Playwright).
2. `rcbot check --once` показывает состояние календаря на 6 месяцев вперёд меньше чем за 2 секунды (режим API).
3. `rcbot simulate` поднимает Telegram, ntfy и звонок; повторы останавливаются после нажатия «Вижу».
4. Бот работает 48 часов подряд без вмешательства; в отчёте видно число проверок, близкое к расчётному (около 4 300 в сутки при 20 с).
5. После перезагрузки ноутбука бот стартует сам и присылает сообщение о запуске.
6. При отключении интернета на 5 минут бот восстанавливается сам; «сторож» присылает сообщение о простое.
7. В логах, БД, фикстурах и на диске нет пароля, номера документа, cookies.
8. Размер папки после недели работы — меньше 300 МБ (включая Chromium).
9. Интервал ниже 10 с задать нельзя ни через `.env`, ни через Telegram.
10. `rcbot uninstall` не оставляет секретов в Credential Manager и задания в Планировщике.

## 9. Принятые решения (открытых вопросов нет)

Все вопросы закрыты решением по умолчанию. Ни один из них не блокирует разработку: где данных пока нет, бот сам их собирает и сам переключается.

| № | Вопрос | Решение |
|---|---|---|
| D1 | Формат API `agenda_sae_api_disponibilidades` неизвестен | **Бот работает с первого дня через `DomSource`** (чтение календаря в браузере, проверено на макете). В фазе 0 Claude Code сам запускает `rcbot discover` на ноутбуке владельца, читает очищенный дамп и пишет `ApiSource` с парсером и фикстурами. Как только `ApiSource` проходит тесты, он становится основным, `DomSource` остаётся запасным. Владелец только входит в аккаунт один раз. |
| D2 | Сколько живёт сессия | Неважно: бот входит заново автоматически при первом признаке истёкшей сессии, лимит 6 входов в час. Время жизни сессии пишется в статистику. |
| D3 | Требует ли сайт шаг 1 после нового входа | Черновик уже стоит на шаге «Agenda», поэтому бот открывает шаг 2 напрямую по URL. Если сайт всё-таки откроет шаг 1, бот **не решает контрольный вопрос**, а присылает в Telegram сообщение с кнопкой «Готово»: владелец один раз проходит шаг 1 в своём браузере (меньше минуты), нажимает «Готово», опрос продолжается. Звонок при этом не используется. |
| D4 | Частота запросов | Автоматическая лестница: первые 6 часов — 60 с, следующие 12 часов — 30 с, дальше 20 с. При 403, 429 или странице блокировки — шаг назад, пауза 15 минут, сообщение владельцу. Минимум 10 с зашит в код. |
| D5 | Конфликт сессий бота и владельца | После уведомления о слотах бот 10 минут не входит заново, чтобы не выкинуть владельца. В остальное время конфликт не важен: бот просто входит заново. |
| D6 | Запись через SAE | `SaeSource` выключен. Ответ MEC на разработку не влияет. |
| D7 | Playwright и Python 3.14 | `rcbot doctor` проверяет установку. Если Playwright не ставится на 3.14, вход и `DomSource` автоматически запускаются во вспомогательном окружении: `uv python install 3.13` + отдельный `.venv-browser`, связь с основным процессом через JSON в stdout. Основной бот остаётся на 3.14. Решение принимает `rcbot doctor` сам. |
| D8 | Параметры CallMeBot | Проверяются командой `rcbot simulate`. Если звонок не проходит, бот сообщает в Telegram и продолжает работать на двух каналах. Язык голоса по умолчанию `ru-RU-Standard-A`; при ошибке — `en-US-Standard-B` с английским текстом. |

### 9.1. Что делает владелец (всё остальное делает Claude Code)

1. Установить Python 3.14 и `uv`.
2. Создать бота у @BotFather и написать ему `/start`.
3. Поставить на телефон приложение ntfy.
4. Написать `/start` боту @CallMeBot_txtbot и разрешить звонки.
5. Положить `SPEC.md` в `Desktop\RegistroBot\` и запустить там Claude Code.
6. Когда Claude Code попросит: ввести пароль и токены в мастер `rcbot init`, один раз войти в gub.uy в окне `rcbot discover`, подписаться на тему ntfy, ответить на тестовый звонок.
