# Журнал изменений: registro-civil-bot

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Изменения монорепозитория в
целом — в корневом `CHANGELOG.md`; правил для AI-ассистентов — в `.ai/CHANGELOG.md`.

## [Не выпущено]

### Добавлено

- **Этап 2 «Тесты».** 2822 теста: юнит, интеграция (настоящая SQLite, Chromium на локальных
  страницах, локальный TLS), сквозные сценарии SPEC 7 и скорость, приватность, архитектурные
  инварианты. Покрытие `domain` и `application` — 99,7 % (порог 85 %). Зависимости для тестов:
  `hypothesis`, `trustme`, `pytest-timeout`; `aioresponses` убрана (R7).
- Настройка `RCBOT_JOURNAL_BACKGROUND` (запись журнала в фоновом потоке, по умолчанию `true`).
- Решения R8 (браузер: Chrome первым, затем Edge) и R9 (итоги этапа 2) в `docs/open-questions.md`.

### Исправлено

- Тестами найдено и исправлено: пауза и интервал вне допустимых значений (`/pause`, NaN);
  сортировка слотов; гонки записи журнала и квоты; cookies терялись при пересоздании сессии
  `SafeHttp` и тратили лимит входов; номер этапа попадал в БД; страница входа определялась
  подстрокой адреса; нестабильная остановка процесса.
- `SafeHttp`: запрещены параметры `ssl`, `proxy`, `allow_redirects`; хост сверяется и по urllib, и
  по yarl; `api_url` допускается только на хосте bpmgob; ntfy без текста для push шлёт общую
  фразу вместо текста тревоги.
- `PollLoop` держит минимум между проверками после входа и команд владельца.

- **Этап 1 «Бизнес-логика» (P1–P7).** Конфиг с жёстким минимумом интервала, секреты в
  keyring, домен и детектор, логи с вырезанием секретов, SQLite и миграция `0001`; вход через
  Playwright и `SessionManager`; `DomSource`, каркас `ApiSource`, разведка; цикл опроса с
  лестницей D4 и отступлением; Telegram, ntfy и CallMeBot с повторами до «Вижу»;
  Telegram-интерфейс для владельца; один экземпляр, защита от сна, очистка, отчёт, «сторож»;
  CLI `rcbot` (init, doctor, discover, login, check, run, simulate, purge, uninstall) и скрипты
  Планировщика. На живом сайте не проверялось (этап 3).
- **Журнал наблюдения на рабочем столе (R6).** `Desktop\rcbot-journal`: каждая проверка,
  каждое действие, подробный лог, `openings.csv` с окнами записи, `status.json` с признаком
  «жив / завис»; квота 10 ГБ → 5 ГБ (самые старые дни); настройки `RCBOT_JOURNAL_*`. Защита от
  зависания: таймаут проверки 150 с, монитор живости перезапускает цикл и браузер.

### Подготовка

- Каталог бота в монорепозитории, ТЗ (`SPEC.md`, без номеров заявки владельца), план по фазам,
  инварианты, решения R1–R4.
- Зависимости из SPEC.md 2.1 в общем `uv.lock`: aiohttp 3.14, aiogram 3.31, aiogram-dialog 2.6,
  SQLAlchemy 2.1 + aiosqlite, Alembic, Pydantic 2.13, pydantic-settings, tzdata, sentry-sdk,
  Playwright 1.65, keyring 25.7; для тестов — aioresponses.
- Дымовой тест стека `tests/test_stack.py` (включая запуск Chromium без сети).
- Настройка `RCBOT_TRAMITE_ID` (номер заявки для текста уведомления) в `.env.example`.
- План работ по пяти этапам владельца (решение R5): бизнес-логика, тесты, подключение, аудит,
  работа.
