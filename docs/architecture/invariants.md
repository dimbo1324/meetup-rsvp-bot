# Инварианты: что нельзя ломать

Изменение инварианта требует явного одобрения владельца (`.ai/universal/08-rules-evolution.md`).

1. **Не больше мест, чем лимит.** При любом числе одновременных нажатий занятых мест не больше
   `capacity` (кроме ручного добавления админом с подтверждением). Запись — под `asyncio.Lock` по
   `event_id`, в транзакции `BEGIN IMMEDIATE`, с уникальным частичным индексом
   `(event_id, user_id) WHERE status IN ('active','waitlist')`.
2. **Время.** В БД только UTC (`UtcDateTime`); naive-datetime запрещены; источник времени —
   `Clock`, подменяемый в тестах.
3. **Встречи не удаляются физически**, только отменяются.
4. **Права проверяются на каждом админском действии**, включая callback'и. Владельца нельзя
   удалить из интерфейса.
5. **Слои.** `services/` не знают про Telegram и возвращают значения, а не тексты; handlers не
   обращаются к БД.
6. **Бан привязан к Telegram user ID** и не снимается анонимизацией данных. Без явного действия
   админа никого не баним (отметка явки не истекает в бан).
7. **Схема меняется только миграциями Alembic**; применённые миграции не правятся.
8. **Секреты только в `.env`.** Токен бота нет ни в git, ни в образе, ни в GitHub Secrets.
9. **Идемпотентность планировщика.** Отметка о выполнении ставится в той же транзакции; повторный
   тик не создаёт дубль встречи и не шлёт повторное напоминание.
10. **Лимиты Telegram.** `callback_data` ≤ 64 байт, всплывающий ответ ≤ 200 символов, подпись с
    фото ≤ 1024, текст ≤ 4096 — рендер гарантирует.
11. **Всё пользовательское в постах экранируется** (`html.escape`).
12. **Один токен — один процесс.** У каждого разработчика свой тестовый бот.
