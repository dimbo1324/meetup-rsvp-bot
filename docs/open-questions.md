Живой документ. Решения владельца сначала записываются здесь, затем переносятся в разделы
5–7 `docs/spec/`, а вопрос закрывается. Решения, принятые «только в чате», невидимы следующей
сессии — поэтому записывайте их сюда.

## 2. Открытые вопросы к заказчику

Первая часть вопросов закрыта комментариями к ТЗ от 2026-10-25 (решения — в разделе 1, значения
перенесены в разделы 4, 5, 7 спецификации). Ниже — только то, что осталось.

### 2.1. Ждём ответа

До ответа действует значение по умолчанию.

| # | Вопрос | Значение по умолчанию до ответа |
|---|---|---|
| 1 | Во сколько начинается встреча и какое место постоянное (комментарий заказчика: «оба под вопросом»)? Сколько длится встреча? | 17:00 ⚠️, место задаёт админ при создании встречи |
| 2 | Telegram ID соведущих, которым нужен доступ админа | Только владельцы из `OWNER_IDS` |
| 3 | Какие именно чаты (названия, количество)? Нужен ли отдельный служебный чат для сообщений бота | Один служебный чат (`SERVICE_CHAT_ID`) |
| 4 | Записываться может кто угодно, у кого есть пост, или только участники наших чатов? (Проверка членства требует, чтобы бот был в этих чатах) | Кто угодно |
| 5 | Ответ «да» на «имена всем или только счётчик, имена админам»: прочитан как «только счётчик, имена видят админы» (стр. 2 и 5 ТЗ говорят это прямо). Подтвердить | Имена скрыты |

### 2.2. Рекомендации лида: ждут подтверждения заказчика

Сформулированы как ответы «идеального заказчика» на вопросы лида. Если заказчик подтвердит — переезжают
в раздел 1; если ответит иначе — берём его вариант и дорабатываем.

| # | Тема | Рекомендация |
|---|---|---|
| R1 | Закрытие записи | По умолчанию запись открыта до начала встречи; админ закрывает вручную кнопкой в карточке. При создании встречи можно задать «закрыть за N часов до начала» |
| R2 | Запись после начала встречи | Закрывается в момент начала: запись на идущую встречу бессмысленна и портит учёт явки |
| R3 | Очередь в посте | Строка «В очереди: N» без имён; при пустой очереди скрыта |
| R4 | Автосоздание | Включено; создаёт встречу «через 1 день после прошлой» в 10:00 с параметрами предыдущей; переключатель «выкл» для нерегулярных встреч |
| R5 | Мастер создания | Подставляет время и место из предыдущей встречи |
| R6 | Запрос явки | Через 5 часов после начала (настройка); напоминание админу наутро — уже есть |
| R7 | Очередь и личные сообщения | Если человек из очереди не нажимал «Старт» и сообщение не дойдёт, место всё равно за ним, админ видит это в списке |
| R8 | Админы | Добавляет и убирает админов только владелец; соведущие этого не могут |
| R9 | Служебный чат | Отдельный: заполнение встречи, отмены, ошибки не должны идти в личку владельцу |
| R10 | Две локации и дни (на будущее) | У каждой встречи свои места, список и место проведения; бан и чёрный список общие (иначе бан обходится). Нужны несколько шаблонов автосоздания и общий список встреч для рассылки (бэклог) |
| R11 | Запуск | 1–2 недели в тестовой группе с 2–3 знакомыми, затем боевые чаты; раз в неделю — просмотр чёрного списка |
