# План работ и прогресс

Живой документ: единственное место, где записано, **что запланировано, в каком порядке и что
сделано**. Продуктовое описание — `docs/spec/`. Правила обновления — `.ai/project/13-progress-tracking.md`.

**Как найти следующую веху:** первая веха ниже без строки `**Статус.**`. Порядок вех обязателен;
пропуск — только по решению владельца, записанному в `docs/open-questions.md`.

Оценки даны для двух разработчиков, работающих по вечерам и выходным. **A** и **B** — условное
разделение: A ведёт ядро и данные, B — Telegram-интерфейс и инфраструктуру.

## 2. Вехи подробно

### M0. Каркас

**Статус.** Готово 2026-10-23. Поставлено: структура репозитория и `pyproject.toml` (Python 3.14,
uv, ruff, mypy, pytest), `src/meetup_bot` с `config`, `clock` (`SystemClock`, `FakeClock`) и
`db` (`Base`, `UtcDateTime`, движок с PRAGMA SQLite), Alembic с асинхронным `env.py` (миграций
пока нет), `Dockerfile`, `compose.yaml`, CI (`.github/workflows/ci.yml`), pre-commit, `dev.py`
(`doctor`, `setup`, `quality-gate`, `sync-agents` и др.), система правил для AI-ассистентов
(`.ai/`, `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.codex/`), спецификация разбита на `docs/spec/`.
Не сделано из M0: `deploy.yml` (перенесён в M7), создание тестовых ботов (на стороне владельца).

### M1. Ядро записи

Читать: `docs/spec/05-business-logic.md` (5.1–5.4, 5.10), `10-data-model.md`, `09-architecture.md` (9.3).
Тест-кейсы: 1–6, 17–19 из `docs/spec/16-testing.md`.

**Статус.** Готово 2026-10-23. Поставлено: модели всех таблиц раздела 10 и миграция `0001` (проверяется
тестом `alembic check`); `BEGIN IMMEDIATE` и PRAGMA в движке SQLite; `services/timing` (моменты 5.2,
инварианты, `America/Montevideo`); репозитории events/registrations/users/bans/audit;
`services/events` (создание встречи); `services/registration` (`register` по 5.3, `cancel` по 5.4,
блокировка по `event_id`, значения-результаты, аудит; лист ожидания и «+1» за флагами
`RegistrationOptions`); `renderer/post` (текст, клавиатура, хеш, экранирование, лимиты 1024/4096,
обрезка HTML); `services/posts.load_post_data`. Тесты: кейсы 1–6, 17–19 зелёные, покрытие
сервисов 97–100%. Не входит в M1 (по плану): продвижение из очереди при освобождении места и
увеличении лимита (M9, кейс 12), правка лимита и действия админа над встречей (M3),
настройки из БД (M6: пока `ScheduleSettings`/`RegistrationOptions` с значениями по умолчанию).

### M2. Telegram: посты

**Статус.** Готово 2026-10-23 (без автотестов; проверено сквозным прогоном на фейковой сессии бота).
Поставлено: `telegram/` (`PostUpdater` с debounce 1,5 с, повторным проходом и пометкой `is_dead`;
`TelegramNotifier`; `SignupCallback`; клавиатуры; `build_post`), `handlers/` (кнопки записи/отмены с
lazy registration, inline-режим и `chosen_inline_result`, `/start`, `/help`, deep links, `my_chat_member`,
`/dev_shift` в dev, глобальный обработчик ошибок), `middlewares/user`, `app.py` (Bot, Dispatcher,
`allowed_updates`, команды, стартовое сообщение, планировщик, корректная остановка) и `__main__`.
Не входит: меню админа на aiogram-dialog (интерфейс M3/M5/M6), интерфейс отметки явки (`send_attendance_prompt` —
заглушка), проверка на реальном Telegram (нужен тестовый бот).

### Бизнес-логика M3–M6 и M9

**Статус.** Серверная логика готова 2026-10-23 (по решению владельца — без тестов и без Telegram-слоя;
тесты пишутся отдельным этапом). Поставлено:
- M3: `AdminService` (владельцы из `OWNER_IDS`, админы), `EventService` (правка, перенос, лимит,
  закрытие/открытие, отмена, ручная правка моментов; `create_event_as_admin` — защищённый вход),
  `ParticipantService` (ручное добавление/удаление, отмена после дедлайна), `ExportService` (CSV).
- M4: `LifecycleService` (закрытие, завершение, автосоздание), `scheduler/` (тик, задачи, бэкап,
  пульс, таймауты задач).
- M5: `BanService`, `AttendanceService` (отметка, исправление, истечение окна), автобан по неявкам.
- M6: `SettingsService` со схемой, валидацией, аудитом и синхронным снимком; тексты `text.*`.
- M9: `promote_waitlist` (пропуск «+1», `late_promoted`), продвижение при отмене, удалении, росте
  лимита, бане и повторном открытии записи.
- Корень сборки `src/meetup_bot/container.py` связывает сервисы (один реестр блокировок, общий снимок
  настроек, порядок задач планировщика).

Осталось по этим вехам: меню админа (aiogram-dialog), реализации портов `Notifier`/`PostRefresher`,
вызов `build_services` из `__main__`, тесты (кейсы 7–16, 20, 12), подключение `Scheduler.run_forever`.
