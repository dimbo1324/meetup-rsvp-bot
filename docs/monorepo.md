# Устройство монорепозитория

Репозиторий вмещает несколько **независимых** чат-ботов. У каждого свой код, тесты, документы,
план, конфигурация, данные и способ развёртывания; общие — инструменты, правила AI-ассистентов,
CI и один `uv.lock`.

## Раскладка

```
.
├── bots/                        # по каталогу на бота — самостоятельный проект
│   ├── meetup-rsvp-bot/         # Linux-сервер, Docker
│   └── registro-civil-bot/      # ноутбук владельца, Windows
├── packages/                    # общие библиотеки (пока пусто)
├── docs/monorepo.md             # этот документ
├── scripts/                     # инструменты репозитория: monorepo.py, sync_agents.py
├── tests/                       # тесты инструментов репозитория
├── dev.py                       # единая точка входа для рутинных задач
├── pyproject.toml               # виртуальный корень uv workspace, общие dev-инструменты, ruff
├── uv.lock                      # один lock-файл на все боты
├── .ai/ .claude/ .codex/        # правила, агенты и навыки ассистентов
├── CLAUDE.md AGENTS.md          # точки входа ассистентов (AGENTS.md генерируется)
├── task-checklist.md            # чек-лист текущей задачи (один на репозиторий)
└── .github/                     # CI, dependabot, шаблон PR
```

## Контракт каталога бота

`bots/<имя>-bot/` обязан содержать (проверяет `uv run python dev.py check-layout`, он же входит
в `quality-gate` и pre-commit):

| Что | Зачем |
|---|---|
| `pyproject.toml` с `[project].name` и `[tool.monorepo]` | Член uv workspace; `package` — импортируемый пакет, `platform` — `linux-docker` или `windows-desktop`, необязательные `env` (переменные окружения; значения на `.` — пути от каталога бота), `setup` (шаги, которые выполняет `dev.py setup`), `coverage` и `coverage_min` (пакеты и порог покрытия в процентах для полного прогона `dev.py test`) |
| `src/<package>/__init__.py`, `tests/` | Код и тесты; тесты бота запускаются отдельным процессом в его каталоге |
| `README.md`, `CHANGELOG.md` | Для людей: запуск, развёртывание, история изменений бота |
| `.env.example` | Только несекретные настройки и пустые места под секреты; `.env` не коммитится |
| `CLAUDE.md` (+ `.ai/*.md` → сгенерированный `AGENTS.md`) | Правила бота для ассистентов |
| `docs/ROADMAP.md`, `docs/architecture/overview.md`, `docs/open-questions.md` | План, реальное состояние, решения владельца |

Требования бота — `docs/spec/` или `SPEC.md`; инварианты — `docs/architecture/invariants.md`.
Для Docker-ботов — `Dockerfile` с контекстом сборки в корне, разрешающий
`Dockerfile.dockerignore` рядом с ним и `compose.yaml` с `context: ../..`.

Граница между ботами проверяется: код и тесты бота не импортируют пакет другого бота.

## Решения

**Один uv workspace и один `uv.lock`.** Альтернатива — независимый lock у каждого бота. Выбран
общий: боты на одном стеке (Python 3.14, aiogram, SQLAlchemy), одна версия библиотеки на весь
репозиторий, одно обновление зависимостей, один `.venv`, и общий код в `packages/` подключается
без публикации. Цена — обновление общей библиотеки затрагивает всех ботов, поэтому такой PR
проходит полный шлюз. Если боту понадобится несовместимая версия — его выносят из workspace
отдельным решением в этом документе.

**Виртуальный корень.** У корневого `pyproject.toml` нет `[project]`: корень — не пакет, а
набор инструментов. Окружение синхронизируется только `uv sync --all-packages --all-groups`
(`dev.py setup`); `dev.py` вызывает `uv run --all-packages`, чтобы окружение не сужалось до
одного бота.

**Проверки по ботам раздельно.** ruff — один проход по репозиторию (ботовые конфиги наследуют
корень через `extend`); mypy и pytest — в каталоге каждого бота отдельным процессом, со своими
настройками строгости, путями и пакетом `tests`. `quality-gate --bot <бот>` сужает проверку.

**Docker из корня.** Образ бота собирается с контекстом — корнем монорепозитория (нужен общий
`uv.lock`), но BuildKit берёт разрешающий список `bots/<бот>/Dockerfile.dockerignore`: в образ
попадают только корневые `pyproject.toml`, `uv.lock` и файлы этого бота. Корневой
`.dockerignore` — запасная защита секретов для сборок без BuildKit. Зависимости ставятся
`uv sync --frozen --no-dev --package <бот>`, пакет — не editable.

**Правила ассистентов в два уровня.** Общие — `.ai/` корня → `CLAUDE.md` и `AGENTS.md` корня;
бота — `bots/<бот>/.ai/` → `CLAUDE.md` и `AGENTS.md` бота. Claude Code подгружает `CLAUDE.md`
бота при работе в его каталоге, Codex склеивает `AGENTS.md` от корня до рабочего каталога,
поэтому бюджет 30 КиБ считается для пары «корень + бот». Агенты без префикса — общие, с
префиксом бота (`meetup-*`, `rcbot-*`) — его специалисты.

**Общий код.** `packages/<имя>/` — участник workspace со своими тестами. Вынос — только когда
код реально нужен двум ботам и стабилен; до этого копия дешевле ранней абстракции.

## Добавить бота

Пошагово — навык `new-bot` (`.claude/skills/new-bot/SKILL.md`). Коротко: каталог по контракту →
`uv lock` → `dev.py setup --bot <бот>` → `dev.py sync-agents` → строка в таблице ботов
`.ai/project/10-project-map.md` и этого документа → CI (Windows-матрица или Docker-матрица,
dependabot) → `dev.py quality-gate`.
