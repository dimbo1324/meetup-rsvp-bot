# Чек-лист задачи: меню админа (aiogram-dialog) и интерфейс отметки явки

Ветка: `feat/admin-menu-dialogs`. Модель работы: лид + 5 агентов реализации (4 возобновлены после лимита) + 1 ревьюер.
Тесты — отдельным этапом (решение владельца).

Обозначения: `+` — сделано, `-` — не сделано или сделано частично.

## Реализация

- [+] Контракты: `dialogs/states.py`, `_common.py`, `__init__.py`, `telegram/attendance_ui.py`
- [+] H1. Главное меню, `/menu`, `/cancel`, встречи (список, карточка, правка, предпросмотр, отмена, CSV)
- [+] H2. Мастер создания встречи; участники встречи
- [+] H3. Выбор пользователя (`request_users`), чёрный список, админы
- [+] H4. Настройки (группы, тексты, часовой пояс)
- [+] H5. Отметка явки (список ✅/🚫, «Готово», исправление, погашение у остальных)
- [+] Сборка: `setup_dialogs`, роутеры, `AttendanceUI` в `app.py`

## Проверка

- [+] `quality-gate` зелёный: ruff, mypy `--strict` (83 файла), 51 тест
- [+] Сквозной прогон на фейковой сессии бота: права не-админа, `/menu`, обход встреч и участников, ввод настройки с валидацией, отметка явки с переключателем → бан, режим исправления
- [+] Независимое ревью: критичных дефектов нет; исправлены циклический импорт (`handlers/_common` → `telegram/common`), залипшая клавиатура пикера при `/cancel`, устаревшие кнопки после рестарта (без шума в служебном чате), `ValueError` у симулированных callback, `OverflowError` при кривой дате
- [-] Не исправлено из ревью (в `docs/open-questions.md`): предпросмотр мастера с фото может превысить подпись 1024; окно редактирования длинного текста сообщения; >90 участников в списке явки; запись `users_known.remember` из диалога с `datetime.now`; гонки двух быстрых нажатий в списке явки; `/start` и `/help` внутри диалога с вводом; уменьшение лимита без подтверждения
- [-] Проверка на реальном Telegram не выполнена
- [-] Автотесты диалогов не написаны
