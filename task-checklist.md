# Чек-лист задачи: registro-civil-bot, этап 1 «Бизнес-логика»

Ветка `feat/rcbot-stage1-business-logic`. Объём — `bots/registro-civil-bot/docs/ROADMAP.md`, Э1
(решение R5): весь код фаз P1–P7 без живого сайта, реальных токенов и внешних сервисов. Тесты —
этап 2; на этапе 1 при каждом коммите обязательны ruff, `mypy --strict`, `check-layout` и
зелёный дымовой тест. Коммит — на каждую фазу.

Обозначения: `+` — сделано, `-` — не сделано или сделано частично.

## Подготовка

- [ ] Ритуал ориентации, ветка, чек-лист закоммичен до кода

## Фазы

- [ ] P1 каркас: `config` (настройки с жёстким минимумом интервала 10 с, секреты в keyring,
      пути от каталога бота), `domain` (модели, события, ошибки), логи с `RedactionFilter`,
      Sentry выключен по умолчанию, БД (WAL) и миграция Alembic, репозитории, CLI `rcbot`
- [ ] P2 вход: Playwright без профиля на диске, cookies только в памяти, `SessionManager`
      (блокировка, ≤ 6 входов в час, 10 минут без входа после тревоги), шаг 1 → `NEEDS_MANUAL`
- [ ] P3 источники: HTTP только к разрешённым хостам, `DomSource` (зелёные дни, плашка «нет
      мест», снимок только календаря), каркас `ApiSource` с карантином, `SaeSource` выключен,
      `rcbot discover` с очисткой дампа до записи на диск
- [ ] P4 детектор и опрос: чистый детектор (появление, изменение, исчезновение после 3 пустых
      проверок), `PollLoop` без дрейфа с разбросом ±10 %, лестница D4, отступление на ошибках,
      переход на `DomSource`, почасовая статистика
- [ ] P5 уведомления: Telegram, ntfy, CallMeBot параллельно, повторы до «Вижу», прогрев
      соединений, запись доставок после отправки, запасной язык звонка (D8)
- [ ] P6 Telegram: только владелец, команды SPEC 2.5, кнопки «Вижу» и «Готово», меню на
      aiogram-dialog (статус, сканирование, уведомления, обслуживание)
- [ ] P7 надёжность: один экземпляр (мьютекс + lock-файл), защита от сна, очистка по срокам,
      ежедневный отчёт, «сторож», корректное завершение, скрипты Планировщика, `purge`, `uninstall`
