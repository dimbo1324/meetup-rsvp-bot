# Выполнение вехи плана работ бота

`<бот>` ниже — каталог `bots/<бот>/`. Одна веха `<бот>/docs/ROADMAP.md` — одна задача. Не
сливайте две вехи в одну и не нарушайте порядок без решения владельца, записанного в
`<бот>/docs/open-questions.md`.

## 1. Ориентация (обязательно)

```powershell
git status --short --branch
git log -15 --date=iso-strict --pretty=format:"%h %cd %s"
```

Затем по порядку: `task-checklist.md` (если остались `[ ]` с прошлой сессии — сначала
разберитесь с ними), `<бот>/CLAUDE.md`, `<бот>/docs/ROADMAP.md` (первая веха без `**Статус.**` —
ваша), `<бот>/docs/architecture/overview.md`, `<бот>/docs/open-questions.md`.

## 2. План

Для крупной или незнакомой вехи делегируйте субагенту `milestone-planner`. Определите
границы, владельцев поведения по слоям, затрагиваемые контракты (БД, внешние API, тексты,
настройки), риски для инвариантов (`<бот>/docs/architecture/invariants.md`) и критерии приёмки.
Заполните `task-checklist.md` пунктами `[ ]` и **закоммитьте до кода**.

## 3. Ветка

```powershell
git checkout main
git pull --ff-only origin main
git checkout -b feat/<бот>-<веха>-краткое-описание
```

## 4. Реализация

Подключайте специалистов бота (`meetup-*` или `rcbot-*`, перечислены в `<бот>/CLAUDE.md`) и
общего `platform`. Обязательные тест-кейсы вехи — из требований бота. Код только в каталоге
бота; общий код — отдельной задачей в `packages/` (правило `12-monorepo.md`).

## 5. Проверка

```powershell
uv run python dev.py quality-gate --bot <бот>
```

Затронут корень (`dev.py`, `scripts/`, `pyproject.toml`, `uv.lock`, правила) — полный
`quality-gate` без `--bot`. Перед финалом — навык `code-review` или субагент `quality-reviewer`.

## 6. Завершение

- Заполните чек-лист значками `+`/`-` честно.
- Добавьте строку `**Статус.**` под вехой в `<бот>/docs/ROADMAP.md` и обновите таблицу §1.
- Обновите `<бот>/docs/architecture/overview.md` и `<бот>/README.md`, если изменение видно
  пользователю; зависимости или выпуск — `<бот>/CHANGELOG.md`.
- Если веха вскрыла устаревшие правила — примените навык `rules-evolution`.
- Если правила бота требуют демонстрации владельцу после вехи — остановитесь и покажите.
- Fast-forward слияние в `main` и пуш — только если владелец явно просил публикацию.
- Итоговый отчёт: что сделано, что проверено, что не сделано.
