# Проект: meetup-rsvp-bot

Telegram-бот для записи на субботние встречи русскоязычного сообщества в Монтевидео:
ограниченное число мест (по умолчанию 10), поимённая запись, бан за неявку, управление
из Telegram без правки кода. Пост рассылается админом через inline-режим (`@имябота`),
счётчик общий для всех постов встречи. Полное описание — `docs/spec/`.

## Карта репозитория

Один Python-пакет `meetup_bot` в `src/`, один процесс на `asyncio`, SQLite, long polling.

- `src/meetup_bot/` — код бота. Слои и правила зависимостей — `docs/spec/09-architecture.md`:
  `handlers/`, `dialogs/` → `services/` → `repositories/` → `db/`; `renderer/`, `telegram/`,
  `scheduler/`, `middlewares/`, `texts/`. Сейчас реализован только каркас (`config`, `clock`,
  `db`); реальное состояние — `docs/architecture/overview.md`.
- `tests/` — pytest; основная масса тестов на сервисы с настоящей SQLite в памяти.
- `alembic/`, `alembic.ini` — миграции БД (единственный способ менять схему).
- `docs/spec/` — продуктовая спецификация, разбитая по разделам (индекс — `docs/spec/README.md`).
- `docs/ROADMAP.md` — вехи и статус; `docs/open-questions.md` — решения владельца и открытые
  вопросы; `docs/architecture/` — текущее состояние и инварианты.
- `dev.py` — единая точка входа для рутинных задач (`uv run python dev.py list`).
- `.ai/`, `.claude/`, `.codex/`, `CLAUDE.md`, `AGENTS.md` — система правил для ассистентов.
- `Dockerfile`, `compose.yaml`, `.github/workflows/` — контейнер и CI/CD.

## Язык

- **Русский**: вся документация (включая `.ai/`, `.claude/`, `.codex/`, `CLAUDE.md`,
  `AGENTS.md`, `README.md`, `task-checklist.md`), комментарии и докстринги в коде, сообщения
  коммитов, тексты бота, отчёты владельцу.
- **Английский**: идентификаторы в коде, имена файлов и ключи конфигурации.
- Не смешивайте языки внутри одного документа.

## Политика документации

- Продуктовая спецификация живёт в `docs/spec/` и меняется только при изменении намерения
  продукта. Решения владельца сначала фиксируются в `docs/open-questions.md`, затем
  переносятся в разделы 5–7 спецификации.
- Исключение «не создавать новые документы» (`03-scope-and-code-style.md`) покрывает
  `docs/`, `README.md`, `CHANGELOG.md` и `task-checklist.md`.

## Ограничения продукта (защитные)

- Один токен — один процесс long polling: у каждого разработчика **свой тестовый бот**.
  Боевой токен нигде, кроме `.env` на сервере, не появляется.
- Права проверяются на каждом админском действии; скрытая кнопка защитой не считается.
- Порядок вех `docs/ROADMAP.md` обязателен. Пропуск вех — только по решению владельца,
  записанному в `docs/open-questions.md`.
