# Монорепозиторий: границы ботов и общие стандарты

> **Суть.** Боты независимы: не импортируют друг друга (проверяет `check-layout`), одна задача — один бот, общий код — только в `packages/` и только когда он реально нужен двоим; каталог бота следует контракту `docs/monorepo.md`; один `uv.lock` и Python 3.14 на всех; у каждого разработчика свой тестовый Telegram-бот.

Ботов в репозитории может быть сколько угодно, но каждый остаётся самостоятельным проектом.

## Независимость ботов

- Бот не импортирует пакет другого бота — ни в коде, ни в тестах. Шлюз проверяет это
  (`dev.py check-layout`).
- Общий код выносится в `packages/<имя>/` только когда он **реально** нужен двум ботам и
  стабилен; до этого копия лучше ранней абстракции. Вынос — отдельная задача: пакет-участник
  workspace, свои тесты, запись в `docs/monorepo.md`.
- Одна задача — один бот. Изменение двух ботов сразу допустимо только для общего: корня,
  `packages/`, правил, CI, `uv.lock`.
- Данные, `.env`, бэкапы и токены у каждого бота свои и лежат в его каталоге; ничего из этого
  не коммитится.

## Контракт каталога бота

Проверяется `dev.py check-layout`; описан в `docs/monorepo.md`. Новый бот: каталог
`bots/<имя>-bot/` по контракту, `[tool.monorepo]` (пакет, платформа, окружение, шаги setup),
строка в таблице ботов `10-project-map.md`, при необходимости агенты `<префикс>-*` в обоих
зеркалах. Пошагово — навык `new-bot`.

## Зависимости

- Один `uv.lock` на репозиторий: версии библиотек у ботов совпадают. Новая зависимость
  объявляется в `pyproject.toml` того бота, которому она нужна (общие инструменты разработки —
  в корне), с обоснованием по `05-security-and-secrets.md`.
- Обновление общей библиотеки затрагивает всех ботов, которые её используют: шлюз — полный.
- Python 3.14 у всех ботов (пересечение `requires-python` участников workspace).

## Общие стандарты Python

- Полные аннотации типов; `# type: ignore` всегда с кодом ошибки. Строгость mypy задаёт бот,
  ниже `check_untyped_defs` не опускаться.
- `ruff`: базовая конфигурация корня (линия 100, правило `DTZ` против naive-datetime); бот её
  наследует и только добавляет исключения.
- Время — через абстракцию часов бота, не `datetime.now()` в бизнес-логике.
- Конфигурация — из переменных окружения через pydantic-settings, не из констант.
- Точка входа бота `__main__.py` — только разбор запуска и сборка.

## Telegram-боты

- Один токен — один процесс long polling: у каждого разработчика **свой тестовый бот**.
  Боевой токен живёт только там, где бот работает (`.env` на сервере или хранилище секретов
  ОС), и нигде больше.
