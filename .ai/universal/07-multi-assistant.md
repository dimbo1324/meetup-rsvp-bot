# Совместная работа нескольких ассистентов

> **Суть.** Git — поверхность координации: смотрите свежие историю и статус, не переписывайте чужие ветки, правки правил — в модулях один раз, зеркала .claude/.codex правятся парами, состояние восстанавливается из файлов.

Назначение: несколько AI-ассистентов и людей работают в репозитории в разных сессиях;
git — поверхность координации, а модули правил — общие.

## Координация через git

- Перед нетривиальной работой выполните
  `git log -10 --date=iso-strict --pretty=format:"%h %cd %s"` и
  `git status --short --branch`: свежие коммиты могут быть законченной работой другого
  ассистента — её не нужно переделывать или оспаривать.
- Никогда не переписывайте историю чужой ветки, над которой идёт работа. Стройте поверх
  неё или спросите.
- Рабочие ветки у каждого ассистента свои. Ассистент не коммитит в `main` напрямую
  (см. `01-workflow.md`).
- Коммиты атрибутируются (трейлер с идентификатором ассистента по принятому соглашению).

## Общие модули правил

- Все ассистенты подчиняются одним правилам из `.ai/universal/` и `.ai/project/`.
  Источник истины ровно один.
- `CLAUDE.md` подключает модули нативными `@`-импортами; `AGENTS.md` ГЕНЕРИРУЕТСЯ из них.
  Не правьте `AGENTS.md` руками: меняйте модуль и запускайте синхронизацию (см. модуль
  команд проекта).
- Если задача меняет общее поведение (процесс, шлюзы, стиль, ограничения), меняйте модуль
  один раз — подхватят все ассистенты. Зеркальные файлы (`.claude/` и `.codex/`: агенты и
  навыки) правятся одинаково на обеих сторонах в одной и той же задаче.

## Гигиена сессии для любой модели

- Перечитывайте планы и файлы правил с диска, а не доверяйте памяти прошлой сессии:
  между сессиями файлы меняются.
- Когда контекст шаткий или задача большая, пересформулируйте критерии приёмки в чек-листе
  до кодинга и сверяйтесь с файлами, а не с воспоминаниями.
- Если два правила конфликтуют: модуль проекта главнее универсального; явное указание
  владельца в текущем диалоге главнее обоих. Скажите вслух, какое правило выбрали и почему.
- Состояние проекта восстанавливается из файлов (см. `13-progress-tracking.md`), а не из
  истории чата. Закончили этап — обновите документы состояния, чтобы следующий ассистент
  подхватил работу без вас.
