# Время и метки времени: дата без момента — не дата

> **Суть.** Читайте и сообщайте каждую дату с полной точностью — часы, минуты, секунды, зона. Для git: `--date=iso-strict`; `--oneline`, `--date=short` и «2 дня назад» не отвечают на вопрос «когда».

Назначение: дата без времени не упорядочит два события одного дня, а в проекте несколько
коммитов в день — обычное дело.

## Правило

Берёте ли вы информацию с датой — коммит, mtime файла, строку истории, запись лога, релиз,
запись БД — берите **полный момент**: часы, минуты, секунды и часовой пояс (или явную
пометку UTC). Сообщайте так же.

Запрещено как *ответ* на вопрос «когда это произошло»: только относительное время
(«2 дня назад»); только дата без времени; `git log --oneline`; метка без зоны и без
указания, что это UTC. Относительное время допустимо как *дополнение* к точному.

## Git

Все команды только для чтения:

```powershell
git log -15 --date=iso-strict --pretty=format:"%h %cd %s"   # история с датами коммитов
git show -s --format=fuller --date=iso-strict <ref>         # один коммит: автор И коммиттер
git log -1 --date=iso-strict --format=%cd -- <путь>         # когда файл менялся последний раз
```

`%cd` (дата коммиттера) показывает порядок реального попадания в историю; `%ad` (дата
автора) переживает rebase и cherry-pick, так что они расходятся чаще, чем кажется.

## В коде и артефактах

- Метка, записанная в артефакт, лог, строку БД или интерфейс, содержит секунды.
- Храните полный момент (UTC) даже если отображение грубее: утраченную точность не вернуть.
- Всегда указывайте зону. В этом проекте в БД всё хранится в UTC, а на экран выводится в
  часовом поясе из настроек; naive-datetime запрещены, время берётся только из `Clock`.
