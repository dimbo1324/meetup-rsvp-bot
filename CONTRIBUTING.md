# Как работать с репозиторием

Репозиторий — монорепозиторий независимых ботов (`docs/monorepo.md`). Всё ниже относится ко
всем ботам; особенности бота — в его `README.md` и `CLAUDE.md`.

## Ветки и слияние

- `main` защищён договорённостью: прямо в него коммитит только владелец. Все остальные (люди и
  AI-ассистенты) работают в ветках `feat/…`, `fix/…`, `chore/…`, `docs/…` и вливают их через
  pull request либо fast-forward слиянием по просьбе владельца.
- Коммиты — в стиле Conventional Commits, по-русски: `feat: запись с гостем +1`.
- Перед слиянием — зелёный `uv run python dev.py quality-gate` (или `--bot <бот>`, если
  изменения только в одном боте).

## Порядок работы над задачей

1. Ритуал ориентации: `git status`, `git log`, `task-checklist.md`, затем документы бота —
   `docs/ROADMAP.md`, `docs/architecture/overview.md`, `docs/open-questions.md`.
2. Заполнить `task-checklist.md` и закоммитить до кода.
3. Реализовать, покрыть тестами (сценарии — в требованиях бота).
4. Схема БД — только через миграцию Alembic.
5. Обновить документы состояния бота (`ROADMAP.md`, `overview.md`, при необходимости
   требования).
6. Одна задача — один бот. Общий код — отдельной задачей в `packages/`.
7. Свой тестовый Telegram-бот у каждого разработчика; боевой токен никогда не используется
   локально.

## Язык

Документация, комментарии и сообщения коммитов — на русском; идентификаторы в коде — на английском.

## Секреты и персональные данные

В git нет токенов, `.env` и персональных данных. Только `.env.example`. Утёкший токен
перевыпускается (для Telegram — через BotFather, `/revoke`).

## Правила для AI-ассистентов

Лежат в `.ai/` и `bots/<бот>/.ai/`; см. `.ai/README.md`, `CLAUDE.md`, `AGENTS.md`.
