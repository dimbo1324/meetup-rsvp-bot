# Как работать с репозиторием

## Ветки и слияние

- `main` защищён договорённостью: прямо в него коммитит только владелец. Все остальные (люди и
  AI-ассистенты) работают в ветках `feat/…`, `fix/…`, `chore/…`, `docs/…` и вливают их через
  pull request либо fast-forward слиянием по просьбе владельца.
- Коммиты — в стиле Conventional Commits, по-русски: `feat: запись с гостем +1`.
- Перед слиянием — зелёный `uv run python dev.py quality-gate`.

## Порядок работы над задачей

1. Ритуал ориентации: `git status`, `git log`, `docs/ROADMAP.md`, `docs/architecture/overview.md`,
   `task-checklist.md`, `docs/open-questions.md`.
2. Заполнить `task-checklist.md` и закоммитить до кода.
3. Реализовать, покрыть тестами (сценарии — `docs/spec/16-testing.md`).
4. Схема БД — только через миграцию Alembic.
5. Обновить документы состояния (`docs/ROADMAP.md`, `docs/architecture/overview.md`, при
   необходимости `docs/spec/`).
6. Свой тестовый бот у каждого разработчика; боевой токен никогда не используется локально.

## Язык

Документация, комментарии и сообщения коммитов — на русском; идентификаторы в коде — на английском.

## Секреты

В git нет токенов и `.env`. Только `.env.example`. Утёкший токен перевыпускается через BotFather (`/revoke`).

## Правила для AI-ассистентов

Лежат в `.ai/`; см. `.ai/README.md`, `CLAUDE.md`, `AGENTS.md`.
